# Derive a transformation product (tp-03), built

(`crates/mzdraw/src/tp.rs` (`derive`), `commands.rs` (`tp:derive`, `derive_args`), `editor_pathway.rs` (`Editor::tp_derive`), `context.rs` (item `tp.derive`), `editor_tools.rs` (Shift+D); tests `crates/mzdraw/tests/tp.rs`; golden cases `tests/data/log/tp-derive.json`; e2e: one step of `tests/e2e.mjs`; screenshots at deviceScaleFactor 2 `docs/shots/tp03-{derived,edited}.png`; independent check `tools/fidelity/derive.py`, reference `tests/data/fidelity/derive.json`.) No `draw_edit/1` op or field is new.

- **`tp:derive`** `{"of":ATOM,"patch":[OPS],"at":[X,Y]}` (`patch`, `at` optional) is one undo step whose log is plain ops. It lists: `atom.set map` on the parent atoms that have none (in id order, after the largest map of the drawing, so 1..n on a fresh parent); the copy of the structure that holds `of` (atoms with charge, isotope, radical, explicit H, label; bonds with orders and wedges; NOT data, annotation or unknown fields), with the source's maps; the patch; an anchored arrow (`from` smallest parent atom, `to` smallest surviving copy atom) routed by `route::route_in`.
- **Patch.** `draw_edit/1` operations written on the PARENT's atom and bond ids and coordinates: `atom.add`, `bond.add`, `atom.set`, `bond.set`, `atom.data`, `atom.ann`, `move`, `rotate`, `flip`, `remove` (atoms and bonds; no objects). Parent ids become the copy's, coordinates are translated with the copy, `-1`, `-2`... name the first, second... `atom.add` of the patch (`tp::NEW`; the negative form is a convention of the request, turned into `NEW + k` before `Op::parse`). A new atom gets the next free map (largest map of the drawing + 1) unless the patch gives one, so a map number names one atom across the pathway, TP2 derived from TP1 included. Scaffold kept: nothing is cleaned up.
- **Placement.** `at` is the centre of the copy's box. Without it: one column right of the parent (`pathway.col_gap`) at its height; where that is taken by another structure, below the lowest box in the way (`pathway.row_gap`), so TPs of one parent stack in that column.
- **Refusals** (verdict, `failed.stage` `command`, nothing written; exit 1): `error.draw2.tpPatch` (an atom of the copy over the largest allowed valence of its element and charge, where its parent atom was not already over; an id the parent lacks; an operation the patch may not hold; more than 10,000 ops), `error.draw2.tpMaps` (a map above 999 would be needed: a parent that lacks maps and has more than 999 atoms), `error.draw2.tpSize` (parent above 5,000 atoms), `error.draw2.noAtom`. A malformed `args` is `error.draw2.request` (invalid request). An atom left alone after a cleavage is fine.
- **Page.** "Derive TP" in the menu of an atom and of a selection (`tp.derive`, key Shift+D), and Shift+D on the focused or selected atom (`Editor::tp_derive`: the same call with an empty patch). The copy is selected and the tool is Select, so the next edit (Alt+Arrow, the mouse) applies to it. Said in the live line (`draw2.say.derived`). Texts in `web/lang/mzdraw.js`.
- **Request table.** One row `tp:derive` in the section `command` and the mention in the `commands` row (D13); `docs/mzdraw.md` and `edit-schema.json` moved by that.
- **Proof.** `tests/tp.rs`: translation + maps of every copy atom, maps unique per structure and the same atom across TP1/TP2 and the three TPs, empty patch gives the same SMILES, undo returns the identical document (maps of the parent included), refusals, 1000 atoms refused / 999 accepted, log replays to the same bytes, dry run, bad shapes, Shift+D and the menu item, time bound (900 atoms twice < 5 s; debug build). Goldens wasm == native in `tp-derive.json` (three TPs, TP of a TP, `at`, plain derive, and four verdicts). e2e: right-click, long press (touch) and Shift+D; page equals the golden (document and SVG); one undo each. `tools/fidelity/derive.py` (RDKit 2026.09.2, 2026-11-21, 3/3): RDKit reads our RXN V2000 of each parent -> TP; the mapped atoms are the same atoms and the formula delta equals the delta written by hand.

Not built / not measured: the kill test (velocity task "parent and 5 TPs" against copy-paste-and-edit) is NOT run: the task is not added to plan-02, so the context-menu item and key stay by default. No randomised property test over arbitrary patches (deterministic cases only). Patch cannot hold object operations or `ring`. A map-less export (CDXML, CML) loses the maps as plan-11 says.
