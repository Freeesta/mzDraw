# Derive a transformation product (tp-03), built

(`crates/mzdraw/src/tp.rs` (`derive`), `commands.rs` (`tp:derive`, `derive_args`), `editor_pathway.rs` (`Editor::tp_derive`), `context.rs` (item `tp.derive`), `editor_tools.rs` (Shift+D), `settings.rs` (`pathway.derive`); tests `crates/mzdraw/tests/tp.rs`; golden cases `tests/data/log/tp-derive.json`; e2e: three steps of `tests/e2e.mjs`; screenshots at deviceScaleFactor 2 `docs/shots/tp03-{parent,derived,edited}.png`; independent check `tools/fidelity/derive.py`, reference `tests/data/fidelity/derive.json`; kill test `tests/data/velocity/` task `parent-five-tps`.) No `draw_edit/1` op or field is new.

- **`tp:derive`** `{"of":ATOM,"patch":[OPS],"at":[X,Y]}` (`patch`, `at` optional) is one undo step whose log is plain ops. It lists: `atom.set map` on the parent atoms that have none (in id order, after the largest map of the drawing, so 1..n on a fresh parent); the copy of the structure that holds `of` (atoms with charge, isotope, radical, explicit H, label; bonds with orders and wedges; NOT data, annotation or unknown fields), with the source's maps; the patch; an anchored arrow (`from` smallest parent atom, `to` smallest surviving copy atom) routed by `route::route_in`.
- **Patch.** `draw_edit/1` operations written on the PARENT's atom and bond ids and coordinates: `atom.add`, `bond.add`, `atom.set`, `bond.set`, `atom.data`, `atom.ann`, `move`, `rotate`, `flip`, `remove` (atoms and bonds; no objects). Parent ids become the copy's, coordinates are translated with the copy, `-1`, `-2`... name the first, second... `atom.add` of the patch (`tp::NEW`; the negative form is a convention of the request, turned into `NEW + k` before `Op::parse`). A new atom gets the next free map (largest map of the drawing + 1) unless the patch gives one. A map number the patch gives (`atom.add` / `atom.set`) must be free in the drawing and among the patch's own, or be the atom's own: else `error.draw2.tpMapDup` (a map names one atom across the pathway). Scaffold kept: nothing is cleaned up.
- **Placement.** `at` is the centre of the copy's box. Without it: one column right of the parent (`pathway.col_gap`) at its height; where that is taken, below the lowest box in the way (`pathway.row_gap`), in one sorted pass.
- **Validity.** The copy as the patch leaves it is checked on a document of the parent alone: no atom over the largest valence `mzlab-mol` allows for its element and charge (`allowed_valences`, unless its parent atom already was), and the copy must be a record `Mol::validate` accepts. The `mzlab-mol` record has no valence rule, so the valence check is the allowed set of `mzlab-mol` itself, not a hand-made table. Bond orders are Kekule 1..3 in this document (no aromatic order exists to check); an order 0 or 4, a bond to the same atom, a second bond between two atoms are refused (tested).
- **Refusals** (verdict, `failed.stage` `command`, nothing written; exit 1): `error.draw2.tpPatch` (valence, an id the parent lacks, an operation a patch may not hold, an invalid record; a patch above 10,000 operations is an invalid request with this key), `error.draw2.tpMaps` (a map above 999 would be needed: a parent that lacks maps and has more than 999 atoms), `error.draw2.tpMapDup`, `error.draw2.tpSize` (parent above 5,000 atoms: reachable by a parent whose atoms all carry maps), `error.draw2.noAtom`. A malformed `args` is `error.draw2.request`. An atom left alone after a cleavage is fine.
- **Page; off by default.** "Derive TP" in the menu of an atom and of a selection (`tp.derive`) and Shift+D (`Editor::tp_derive`: the same call with an empty patch) are offered only when the setting `pathway.derive=on` (key `pathway.derive` of the settings file, written only when on). **Why off:** the kill test below measured 28 actions with Derive TP against 34 with copy-paste-and-edit (ratio 0.82; the rule asked for at most 0.5), so the page route is not the default. The command `tp:derive` (CLI, agents) is always available and is not gated. When on, the copy is selected and the tool is Select; said in the live line (`draw2.say.derived`). A key help line `draw2.keys.derive` is in the keyboard list. Texts in `web/lang/mzdraw.js`.
- **Request table.** One row `tp:derive` in the section `command`, the mention in the `commands` row, and `derive` in the `pathway.*` row of `set` (D13); `docs/mzdraw.md` and `edit-schema.json` moved by that.
- **Kill test** (`tests/data/velocity/tasks.json` `parent-five-tps`: methylcyclohexane and five TPs: a demethylation, two hydroxylations, a ring opening, a hydroxylation of the first hydroxylation product (a TP of a TP)). Shortest hand-written page paths, measured by `node tests/velocity.mjs --check`: **Derive TP 28 actions** (settings `pathway.derive=on` applied before the first action, not counted), **copy-paste-and-edit 34** (Ctrl+A, Ctrl+C, then Ctrl+V and a drag per TP, then the edits and 5 arrows by the arrow tool). The edits are the same in both; what Derive saves is the move of each copy and the arrow (6 of 34, and the selection clicks it needs hold most of that back). Ratio 0.82 > 0.5, so the item and key are off by default. Baseline rows (actions only) are in `baseline.json`; `--guard-test` passes. The agent patch of the task is the page's own log of the Derive path (125 ops), replayed natively to the target.
- **Cost.** Everything is checked and routed on a document of the parent alone, so one derive costs the size of the parent, plus one pass over the drawing for the structures. Two shared hot spots were quadratic and are now linear: `layout::pieces` (an adjacency table instead of a scan of the bonds per atom) and `route::Structures::new` (each box is computed on a document of its own structure). Test `the_cost_of_a_derive_grows_linearly_with_the_drawing` (n and 2n structures, floor against noise) fails on the old code (ratio 3.7: 0.31 s and 1.15 s at 1000 and 2000 structures) and passes on the new.
- **Proof.** `tests/tp.rs` (16): translation + maps of every copy atom, maps unique per structure and the same atom across TP1/TP2, empty patch gives the same SMILES, undo returns the identical document (maps included), refusals (all five keys), 1000 atoms refused / 999 accepted, log replays to the same bytes, dry run, bad shapes, the gate (off: no item, no key), Shift+D and the item, scaling. Goldens wasm == native in `tp-derive.json`. e2e: default off; right-click, Shift+D, long press (touch) and the barrel button (pen), each equal to the golden document and SVG, one undo each; a chemical edit of the copy through the menu replays from the log. `tools/fidelity/derive.py` (RDKit 2026.09.2, 2026-11-21, 3/3) reads our RXN V2000 of each parent -> TP and checks, with the maps, that the unedited heavy atoms and bonds are in the product with the same element and order and that the product differs by exactly the atoms and bonds the patch names, and the formula delta; a wrong expectation makes it fail (tried). It does NOT show that the coordinates, the arrow route or the maps are right (RDKit reads connectivity; the maps are our own numbering read back).

Found by this slice, and **not reproducible on the pinned `mzlab` revision any more** (tp-import-equal measured it natively, in the `.wasm` and in Chromium: derived or imported copies that are equal, up to 24, cost milliseconds; see `built/tp-import-equal.md`): the page was reported to slow down sharply as identical molecules pile up. The one real cost is `Mol::canonical()` of `mzlab-mol` on a whole drawing of equal components, which no page path calls; the kill-test paths still edit each TP before the next copy, which is harmless.

Not built: no randomised property test over arbitrary patches (deterministic cases only); a patch cannot hold object operations or `ring`; CDXML and CML lose the maps as plan-11 says.
