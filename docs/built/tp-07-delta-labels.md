# Arrow labels computed from the two structures (tp-07), built

(`crates/mzdraw/src/steplabel.rs`; command wiring `commands.rs`, `editor_pathway.rs`; room for labels in `pathway.rs`; true minus in `scene.rs`; tests `crates/mzdraw/tests/steplabel.rs`, `crates/mzdraw-wasm/tests/glue.rs`; golden `tests/data/log/pathway-label.json`; page: `web/palettes.js`, `web/mzdraw.js`, `web/lang/mzdraw.js`, two e2e steps; proof `tools/fidelity/delta.py` with `tools/fidelity/delta.reference.json`; screenshots `docs/screenshots/tp-07-*.png`.) No `draw_edit/1` op or field is new: the command writes `obj.set` of `text`.

**Command.** `{"command":"pathway:label","args":{"force":bool,"isomer":WORD}}` (both optional), one undo step; the button "Label arrows" (objects palette, `pathway-label`) and the canvas menu item `pathway.label` run the same Rust. For each arrow anchored at both ends to two different structures it writes the formula delta `T - P`, in the spelling of `mzlab_mol::delta::print` (`+O`, `-CH2`, `-Cl+OH`), on the Hill counts of the record (implicit hydrogens included, as `outline.rs` counts). Equal formulas are an isomer: the word of the caller (`isomer`; the page passes the catalog text `draw2.label.isomer`, the CLI default is `isomer`). An end that holds an R group or a net charge is skipped and counted (`skipped`): a delta has no charges. Data holds ASCII `-`; the drawing paints a true minus (U+2212) in the tokens that are signed deltas (`steplabel::display`, used by the arrow text of `scene.rs`).

**Whose label it is, no stored flag.** The text is split on white space. It is rewritten only if empty or if every token is one this command writes: a signed delta (a sign `+`, `-` or U+2212, then what `delta::parse` reads, at least one element), a signed number with exactly 4 decimals, the isomer word. `hydroxylation (CYP)`, `H2O`, `O3`, `NaBH4`, `+O, 37 °C` stay; `force` rewrites all (tested). An isomer word of another language than the caller's is the person's text and is kept (never loses text). The document forbids a line break in the text of an object, and `below` (arch-web-13) is not on `main`, so two tokens are on one line (`+O +15.9949`); a text with a line break cannot exist yet.

**Live line and report.** `draw2.say.labelled` (labelled, kept, skipped) and `draw2.say.labelNone`; `changed` is reported by `draw-result/1` (`commands::reports_change`); an unchanged text is no operation and no undo step.

**Setting** `pathway.label` = `delta` (default, not written to a settings file) | `mass` | `delta+mass` | `name+delta`; a select on the settings panel (schema `choices`).

**Refusals** (exit 1, `failed.stage` `command`, nothing changes): `error.draw2.labelMass` for `mass` and `delta+mass`; `error.draw2.labelSteps` for `name+delta`; `error.draw2.schemeSize` above `pathway::MAX_ARROWS` (1000) anchored arrows, checked before any work; an invalid argument is `error.draw2.request`. Cost: the structures (`layout::pieces`) and the record (`Document::to_mol`) are built once per command and the counts of a structure once however many arrows end in it; 1000 arrows run in about 50 ms in release (test bound 1500 ms release, 20 s debug; the same test fails on a version that rescans the pieces per arrow, tried).

**Room for labels (tp-05 step 5).** `pathway::Edge::label` is the width of the arrow text as painted; the gap between two columns is raised until the visible arrow is at least that long (`GapNote::rule` `label`, after `slope` and `length`). No golden of tp-05 held an arrow text, so none moved; `tests/data/log/pathway-label.json` has the case with labels (a long text widens the gap, a short one does not).

**Request rows** (`schema::REQUEST`): command `pathway:label`, setting `pathway.label`, and the commands list; the two keys are in the command row. `docs/mzdraw.md` and `tests/data/log/edit-schema.json` moved by that, `context-menu.json` by the new menu item (blessed).

**Proof.** `python3 tools/fidelity/delta.py` reads OUR replay output (the labelled document and its molfile), gives each structure to RDKit (`CalcMolFormula`, `ExactMolWt`) and compares the formula difference of the two ends of each arrow with the label we wrote: 8 of 8 of our labels agree (RDKit 2026.9.2, 2026-11-21; the 4 labels that are the person's text are not compared); the RDKit mass shifts are written to the reference file only. What it does not show: the mass labels (not built), anything about charged structures, R groups or the drawing. The mass shifts of the study (`+O` 15.9949, `-CH2` -14.0157, `+C6H8O6` 176.0321, `+SO3` 79.9568, `-H2` -2.0157, `+H2O` 18.0106) are checked in `crates/mzdraw-wasm/tests/glue.rs` against the masses `sel` returns (not typed ones) to 1e-4; `+C6H8O6` is the mass of ascorbic acid, not a difference of two structures.

**Not built.** The mass modes (`mass`, `delta+mass`; they need arch-web-17 through the glue: a mass table is not in `mzlab-mol`, and none is typed here; rounding half to even at 4 decimals is for that slice), step names (`name+delta`, tp-10), the `below` slot (arch-web-13), the property test over seeded derive patches (tp-03 is not on `main`; `delta` is checked on hand-written structures instead), screenshots of `delta+mass`. The kill test (a person's label rewritten) did not fire in any e2e or synthetic case.
