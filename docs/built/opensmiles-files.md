# SMILES files, built (arch-std-09)

(`crates/mzdraw/src/io.rs` `import`, `smiles_record`; `doc.rs` `Atom::title`, `Document::title`; `ops.rs` `Op::AtomTitle`; tests `crates/mzdraw/tests/formats.rs`, golden `tests/data/log/smiles-files.json`.) A SMILES text is read as the "SMILES Files" rules of OpenSMILES 1.0 say (implemented, no text or example copied):

- one SMILES per line; the first space or tab ends it and what follows is the name of the record (a CXSMILES tail `|...|` right after the SMILES stays with it, the name follows the tail); LF and CR/LF end a line (a UTF-8 byte order mark at the start is dropped);
- a blank line and a line that starts with a space or a tab are ignored, and nothing is stripped into the SMILES (before this slice the whole text was trimmed and an indented line was read from its first word);
- each line is read on its own, structures are placed side by side, one per line (as SDF records are). A line that is no SMILES is not read and is said with its line number (counted from 1, blank lines included): note `draw2.import.smilesLine`, one note per line for the first 10 lines, then `draw2.import.smilesMore` with the count of the others; the other lines open (before, one broken line refused the whole text). A text with no line that reads is refused: `error.draw2.smiles` when a line was broken, `error.draw2.import` when no line was a record;
- the 64-record window of the SDF reader holds for SMILES too (`MAX_RECORDS`; the rest is counted in `draw2.import.skipped`).

**Title.** The name of a record becomes the title of its structure: the operation `atom.title` `{"op":"atom.title","id":ID,"title":TEXT}` (exact inverse by the saved atom, like `atom.data`; one line of at most 80 characters, no control character, else `error.draw2.title`; the empty text takes it away; not in the reader of mzLab yet, `mzlab:false` in the schema) keeps it as the field `title` of the first atom of the structure (`more` of the atom, so `mzdraw/1` is unchanged and an older reader keeps it). The page's import and the replay request `import` emit it; the diff of two documents writes it. A drawing is written with the title of its first structure that has one as the first line of its molfile (V2000 and V3000) and of each SDF record (one record per structure, so each has its own); a structure with no title is written as before, with `mzDraw`. A control character inside a name (a tab, say) becomes a space, and a name longer than 80 characters (the width of the molfile title line) is cut to 80 and counted: note `draw2.import.nameCut`. Both are pinned by `names_are_cleaned_and_cut_in_the_open_and_the_work_is_bounded`.

**Bound.** At most 64 lines (`MAX_RECORDS`) are parsed, good or broken together; the other lines are not parsed and are counted (`draw2.import.skipped`). So the work is 64 parses, each bounded by the length of its line, and the scan of the rest is one pass over the input; a text of only broken lines is refused after 64 attempts. The size of the whole input is limited by the page's field and file door, not here.

**Round trip of names.** A name written as the title line of a molfile or an SDF record is not read back into a title on purpose: that line is the title of the file of another program (and the `mzDraw` stamp of our own files), and reading it would give every imported molfile a title it was never asked to have and move every golden. So the test pins the write side (`a_smiles_file_follows_the_rules_of_the_format`: the molfile and each SDF record start with the name, a record with no name with the product name) and the document side (the title survives `to_json` / `from_json`).

**Test changed.** In `tests/formats.rs` the case `"CC(\nCC"` of the list of texts that must be refused became `"CC(\nC("`: lines are read one by one now, so the second line `CC` of the old case opens as a structure and the case is no longer a refusal; the new cases above pin the new behaviour. The e2e expectation of a three-line SMILES file gained the note "3 records ... side by side" for the same reason (an SDF says it too).

**Texts.** `crates/mzdraw/tests/text_keys.rs` checks that every `error.draw2.*` and `draw2.import.*` key the Rust code writes has an English text in `web/lang/mzdraw.js` (it found `error.draw2.title` of this slice and `error.draw2.engineMissing`, a refusal of the CLI glue that had no text).

Not built: reading the title line of a molfile or an SDF record into a title (see above); the title in KET, CDXML or CML; a command or panel to rename a structure (only the operation); SMILES writing as a file with names; the title in `mzlab-cli` (the field is `mzlab:false`). Notes of the import are not part of the replay result: the golden file proves the structures and the bytes out, the unit test the notes.
