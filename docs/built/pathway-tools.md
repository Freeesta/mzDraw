# Anchoring by hand: the arrow tool, `pathway:anchor`, `pathway:route`, built

(tp-02; `crates/mzdraw/src/route.rs` (`structure_at`, `nearest_structure`, `anchor`, `route_all`, `formula_of`), `editor_pathway.rs`, `editor_tools.rs` (arrow tool), `commands.rs`, `context.rs`; tests `crates/mzdraw/tests/pathway_tools.rs`; golden cases `tests/data/log/pathway-tools.json`; e2e: three steps of `tests/e2e.mjs`; screenshots at deviceScaleFactor 2 `docs/shots/tp02-arrow-{anchored,followed,touch}.png`.) No `draw_edit/1` op or field is new: everything is `obj.add`, `obj.set` and `move` of tp-01.

- **Arrow tool.** An arrow dragged from inside one structure to inside another (the box of the structure, labels included, with `route::HIT_SLACK` = 0.25 bond lengths more on every side, so that a press on a bond of a plain carbon chain, whose box is a line, counts) is added with `from` and `to` set (the smallest atom id of each structure) and routed, in the same undo step. An end on empty canvas, both ends in the same structure, a click, or only one end in a structure: the arrow stays free as drawn. The live line: "Arrow anchored: C7H8O → C7H8O2." (`draw2.say.anchored`).
- **`pathway:anchor`** (command `{"command":"pathway:anchor","args":{"arrow":ID}}`; context menu "Anchor to structures", `pathway.anchor`, on an arrow). Each end is anchored to the structure nearest by box distance within 1 bond length (`editor_pathway::REACH`), ties by the smallest atom id; then the arrow is routed. An end with nothing in reach keeps what it had and is said in the live line (`anchorOne`, `anchorNone`); when both ends reach the same structure the end farther from it stays as it was. No step when nothing changes (the page gets no `CHANGED` flag and the live line says "already anchored", `anchorSame`; the same for Route arrows, `routeNone`, and Free ends, `freeNone`). The edge where both ends reach one structure is tested. An id that is not an arrow is `error.draw2.noObject` / `error.draw2.object` (a verdict with `failed.stage` `command` under `report`).
- **`pathway:route`** (command `{"command":"pathway:route"}`; canvas menu "Route arrows", `pathway.route`). Routes every anchored arrow in one step (`move` and `obj.set`, as `route::route`); no operation and no step when nothing moves (idempotent, tested).
- **Free ends** (arrow menu, `pathway.free`): `obj.set {id, from: 0, to: 0}`, one step. Its CLI twin is that op; there is no command of that name.
- **CLI twin (rule 15).** Request `commands` as above; `dry_run` runs the commands and answers one `draw-result/1` (`ok`, `dry_run`, `created`, `removed`, `failed` for a refused command) with no `out` and nothing written; it does not list the ops (the key `patch` is not written yet); tested. The request table has two rows in the new section `command` (`pathway:anchor`, `pathway:route`) of `schema::REQUEST`; the section is named after the request key whose values it lists, as the section `expect` lists the arms of `expect` (D13; `docs/mzdraw.md` and `tests/data/log/edit-schema.json` moved by that, blessed). The log of the page holds the plain ops, so a native replay of it gives the page's bytes (tested in Rust, and in e2e by replaying the page's own log through the module; native == wasm by `tests/parity.mjs` on `tests/data/log/pathway-tools.json`).
- **Keyboard.** The Menu key or Shift+F10 on a selected arrow opens its menu (`A` jumps to "Anchor to structures", Enter runs it); tested in e2e. arch-std-06's command table has not merged, so the two commands have no keys yet.
- **Golden files that moved because of wanted changes:** `context-menu.json` (the canvas menu has "Route arrows", the arrow menu the two pathway items) and `edit-schema.json` (two rows); the e2e step "context menu, mouse" now expects the four ids of an arrow's menu.
- **Kill test** (`the_arrow_tasks_never_anchor_a_wrong_structure`): a two-step chain, a star of four and a parent with three products, 9 arrows, one drag each: 9/9 anchored to the structures they were drawn between, none to another, so the rule "nearest" was not replaced by "only on release inside a box" (the tool already anchors only on release inside a box; "nearest" is the command). On `main` an arrow drawn between two structures has `from` 0 (the new tests fail there).

Velocity (plan-02): the three arrow tasks are in `tests/data/velocity/` (`two-step-chain` 6 actions, `star-of-four` 10, `parent-three-tps` 8; with the reaction task `esterification` that makes four arrow tasks; baseline rows only for the new tasks, the guard is not loosened). The tasks now also check the anchors: an anchored arrow is compared as `arrow||i>j`, `i` and `j` being the creation-order indexes of the structures at its tail and head (`tests/velocity.mjs` `objectsOf`, `crates/mzdraw/tests/velocity_tasks.rs` `objects_of`); a path whose last arrow ends on empty canvas fails (tried). The agent patches give each arrow `from`/`to` and endpoints written by hand, so they are not routed.

e2e: the step "pathway:anchor by keyboard" opens the document of the golden case "pathway:route puts displaced anchored arrows back" of `tests/data/log/pathway-tools.json` (anchored arrows with raw, displaced ends), runs Route arrows from the keyboard (Menu key, R, Enter) and compares the page's `mzdraw` and `svg` with that case (the native replay of the same request, committed), then one undo and redo; the module's replay of the same request equals it too.
