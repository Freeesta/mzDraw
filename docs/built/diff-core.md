# Semantic diff of two documents, built (plan-15)

`crates/mzdraw/src/diff.rs`: `diff(a, b) -> Vec<Op>` matches atoms, bonds and objects by id and writes the patch with operations of the table of `schema` only, in a fixed order: remove bonds, atoms, objects (one `remove` each); add atoms, bonds, objects (in the pool order of `b`); set atoms (`atom.set`, `atom.data`, `atom.ann`), bonds (`bond.set`, with `rev` for swapped ends), objects (`obj.set`); `move`, grouped by equal displacement (an arrow whose end points move with it is one move; a different end point is an `obj.set` in the frame before the move). A new element, or `el` said again, is how an explicit hydrogen count is taken away (the only way the language has), and the label is then said again. A bond with another pair of atoms under the same id, and an object or atom whose id changes kind, are removed and added.

`hunks(a, ops) -> Vec<Hunk>` groups a patch into hunks (`ids`, `ops`) a person can accept one by one: one connected piece of `a` joined by the bonds the patch adds, or one object; an id used by several operations keeps them together; a `remove` or `move` that touches several pieces is split. Any subset of hunks applies in order, to a valid document (tested). It takes `a` as well as the ops (the plan said `hunks(ops)`): two atoms moved by the same displacement are one piece or two only the document says, and splitting one molecule in two hunks would let a person accept half of a move. A patch with `rotate`, `flip` or `ring` (which `diff` never writes) is one hunk.

Door: the replay request `{"diff": {"a": DOC, "b": DOC}}` (a document is an `mzdraw/1` object or its JSON text; the request stands alone, another field is `error.draw2.requestField`) answers `{"ops": [...], "hunks": [{"ids": [...], "ops": [...]}]}`; an unreadable document is `error.draw2.document` (or `documentNewer`). `Editor::diff_with(&doc)` gives the patch from the drawing in the editor. CLI twin: `mzlab-cli mol draw` with that request; the exit code of an invalid document is the keyed error's (exit 2 is mzLab's mapping of the keyed errors, not tested in this repository). No page change.

Tests: `crates/mzdraw/tests/ops.rs` (the random sessions of the undo property, in pairs: `apply(diff(a, b), a)` has the bytes of `b`, `diff(a, a)` is empty, the patch is in the fixed order, any subset of hunks applies, the SMILES of the result is `b`'s); `tests/data/log/diff.json` (section `diffs`, wasm == native by `tests/parity.mjs`; refused requests). Independent proof: `tools/diff/run.py` (RDKit canonical SMILES and InChIKey; reference output `tests/data/diff/reference.json`: 192 pairs of the 200 synthetic structures, bytes equal 192/192, RDKit equal 154/154 compared (38 pairs an edit made invalid on both sides), hunks 192/192).

Not built, said plainly:
- The counter `next` is not reproduced: no operation sets it, so the result of a patch has `next` at the highest id added (the tests compare with `next` of `b`). The order of a pool after a bond or an object is removed and added again is not `b`'s, and applying hunks in order puts the things of a later piece after those of an earlier one (the same drawing, a different pool order; the tests compare by id there).
- Unknown fields (`more` of the document, an atom, a bond or an object other than `data` and `ann`) are not compared: no operation writes them.
- An arrow anchor (`from`, `to`) that names an atom added by another hunk is accepted as written (a free end until that hunk is applied); an object is its own hunk.
- Matching by structure when ids differ (two drawings of different origin) and showing the diff (plan-16).
- A tiny displacement (under 0.00005) is no move; documents are kept to 4 decimals by the operations.
