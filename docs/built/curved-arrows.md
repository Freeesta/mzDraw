# Lone pairs and electron-pushing curved arrows, built

(arch-cd-25; `crates/mzdraw/src/curve.rs`, `editor_curve.rs`; ops in `ops.rs`, rows in `schema.rs`; tests `crates/mzdraw/tests/curve.rs` and the property test `random_step` of `tests/ops.rs`; golden cases `tests/data/log/curve.json`; study rows B11 and G05 of `docs/study/arch-cd.md`.)

**Lone pairs.** `atom.set` takes `lp`, the number of pairs on the atom, 0 to 4 (above four is `error.draw2.lp`); it is kept as the atom field `lp` (written only when above 0, read back by a reader that has no row for it as an unknown field). The pairs are drawn as two dots each at the free sides of the atom: the widest gaps between its bonds first, several in one gap spread evenly, an atom with no bond has them spread round it, the first up (`curve::lp_dirs`; the scene paints them, the SVG has them too). `lp_from_valence` gives the pairs by the valence rules (the electrons of the group less the charge, minus bond orders, hydrogens and radical electrons, in pairs, 0 to 4, for the groups 13 to 17); the command `lonepairs` (`{"atoms": [ids]}`, no argument is every atom) and the page's "Place lone pairs" (Shift+U) write the `atom.set lp` operations that differ, in one undo step.

**Curves.** `obj.add` with `t: "curve"` and `x`, `y`, `x2`, `y2`, `from`, `to` as for an arrow, plus `head` (`full`, the default: a pair; `half`: one electron, a fish-hook head), `bend` (the bow as a fraction of the chord, -3 to 3, positive to the left of the way the curve goes, y up) and `fl`, `tl` (the start / end is the lone pair of the atom `from` / `to`). An end is a point (`from` or `to` 0), an atom, a bond (the middle of the bond) or a lone pair; ids of atoms, bonds and objects share one counter, so the id says which. `obj.set` takes the same fields (`from: 0` frees the end where it stands) and `x`, `y` for the first point (`x2`, `y2` for the second). The ends are checked when the operation runs (`error.draw2.anchor`: an id that is not there, a lone-pair end with no atom, both ends the same; `error.draw2.object`: a bend out of range, two points on one spot, a curve field on another object) and when a document is read. An anchored end stores no point (0, 0 is kept whatever is given): what is drawn comes from the anchor, so two documents that differ only in where an atom stood have the same curve bytes. A curve end on a lone pair of an atom that has none (the pair was taken away by `atom.set lp: 0`) is drawn at the atom. The curve fields (`head`, `bend`, `fl`, `tl`) and the atom field `lp` are kept as fields the document does not model, so a rewrite keeps them as written. An mzDraw older than this one refuses `t: "curve"` (a kind it does not know) and keeps `lp` as an unknown atom field. A document whose `lp` is not a whole number 0 to 4, or whose curve has a `head` other than `full` or `half`, a `bend` out of range or not a number, or a flag that is not a boolean, is refused on read (`error.draw2.document`); it is not read and then silently changed (test `a_document_with_a_pair_count_or_a_curve_field_it_cannot_read_is_refused`).

**The curve follows its anchors without an operation.** What is drawn, hit-tested and digested is computed from the document every time (`curve::ends`, `shape`: a quadratic curve, the atom end kept 0.28 bond lengths from the atom, the pair end where the pair dots are). A moved atom moves the curve and nothing in the document of the curve changes (test `a_curve_follows_its_atoms_without_an_operation`). **A removed anchor turns the end into the point it stood at:** `Remove` rewrites the curves whose anchor goes (the end is the point it stood at, resolved just before the removal, the flag is cleared) and records the object as it was, so the undo is exact (test `removing_an_anchor_makes_the_end_a_point_and_undo_restores_the_anchor`, and the property test with lone pairs and curves of `tests/ops.rs`, which also holds `diff` and the hunks to the same curves).

**The page.** Tools `lonepair` (a click on an atom: one more pair, none after four; key U; with an atom focused U cycles them), `curve:full` (K) and `curve:half` (Shift+K): press on a lone pair, an atom, a bond or an empty spot, release on the target; the bow is chosen on the free side (`free_side_bend`: away from the side of the chord that has more atoms). A selected curve shows a handle in the middle: drag it to bend (`obj.set bend`, one undo step); `,` and `.` bow a selected curve by a tenth to either side. Mouse, pen and finger work as for the other tools (a touch has a wider reach for the pairs). **With the keyboard alone** (no drag): with a curve tool active, Enter on the focused atom names the source (its lone pair when it has one, the atom with Shift+Enter), the arrow keys walk the focus, and Enter on the focused atom draws the curve to it (Shift+Enter: to the bond walked to reach it); Escape cancels a source. The lines `draw2.say.curveFrom`, `curveFromPair`, `curveCancel`, `curve` say each step (e2e step "a curved arrow with the keyboard alone", test `a_curve_is_drawn_with_the_keyboard_alone_and_escape_cancels`). Copy, paste and duplicate keep the pairs and the curves: a curve keeps the anchors that are copied with it, and an end whose anchor stays behind is pasted as the point it stood at; free ends are shifted with the paste. Items in the objects palette; strings `draw2.tool.lonepair`, `draw2.tool.curve.full`, `draw2.tool.curve.half`, `draw2.tool.lonepairs-place`, `draw2.say.*`, `error.draw2.anchor`, `error.draw2.lp`, `draw2.keys.curve`.

**CLI route.** Every function is an operation of `draw_edit/1` (`atom.set lp`, `obj.add t:"curve"`, `obj.set head/bend/from/to/fl/tl`, `remove`) or the command `lonepairs`, replayed natively to the bytes of the page (`tests/data/log/curve.json`, a move after the curve, a removal, a free-in-place, the command; the refused cases carry their keys). The four rows are `mzlab: false` until mzLab adopts them.

**Files.** The loss manifest has the rows `atom.lp` and `object.curve` (kept only by SVG and `mzdraw/1`): CDXML, KET, CML, RXN and the molfiles write neither (the public CDXML and KET documentation define no curved arrow between atoms and lone pairs that this version could write faithfully), and say so. The digest and the loss manifest count a curve; the SVG draws it and the lone pairs.

**Not built.** "Show the result" of the arrows (LATER, with mzLab `mechanism/1`); a limit of arrows per source (MarvinSketch) and the removal of an arrow when its source changes (Marvin JS): here an arrow keeps its end as a point; a choice of which of several lone pairs of one atom a curve leaves (the first pair), and a lone-pair target by the keyboard (the target is an atom or a bond); automatic layout of pushers; CDXML, MRV, KET export of curves and pairs; radical (single-electron) dots; the lens, the guard and `std/1` findings about curves.
