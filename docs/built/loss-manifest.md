# Format loss manifest, built

(plan-22; `crates/mzdraw/src/loss.rs`, `crates/mzdraw/tests/loss.rs`; section 1c of `docs/mzdraw-formats.md`.) `loss(doc, format)` lists, with ids, the things of one drawing that a format drops or changes; `"out":"loss:FORMAT"` writes it as `loss/1` (`{"format":"loss/1","target","items":[{"what","atoms","bonds","objects"}]}`, one item per thing, ordered by `what` then smallest id, the three lists always written, ascending); `{"lossless":"FORMAT"}` is an arm of `expect` (false when the list is not empty, the `detail` names the kinds, a drawing the format cannot write is false). Formats: `molfile`, `molfile-v3000`, `smiles`, `sdf`, `ket`, `cdxml`, `cml`, `rxn`, `svg`, the document. An unknown format is `error.draw2.request`, an unknown arm value `error.draw2.expect`, a drawing above 100,000 things `error.draw2.lossSize`, a drawing a writer refuses its key (`error.draw2.rxnArrow`). No `draw_edit/1` op; one row for the output and one for the arm in the `request` section of the table. No page change.

The table (`loss::TABLE`, rendered in the formats document and compared with it by a test) has a row per feature: abbreviation, annotation, arrow anchor, arrow text, charge, isotope, atom map, radical, data, geometry, the three arrows/objects, R label, unknown fields, the three wedge marks. A cell is `yes`, `no` or `drawing`. A `drawing` cell is decided by writing the file and reading it back, because it depends on the chemistry or the layout: wedge marks (derived again from the stereo, so a mark on a bond that is no centre does not return), the radical in a SMILES, the geometry of a SMILES, an SDF (records side by side) and a reaction file (structures placed about the arrow), the plus signs of a reaction file. For those cells the round trip is the answer, so the property test does not check them independently.

Tests: `crates/mzdraw/tests/loss.rs`. The property writes 500 random drawings (lattice chains of one or two pieces; charges, isotopes, radicals, maps, R labels, abbreviations, wedge marks, data, an annotation, an unknown field, arrows with text and anchors, plus signs, texts) in every format, reads each back and requires the kinds found by `loss::observed` (a comparison by value that does not look at the table) to equal the kinds `loss` lists. Also: an arrow in a molfile, an annotation in SMILES and a wavy bond in V2000 are listed with their ids; the order; a table that forgets the objects of SMILES differs from the round trip; every feature has a row; a drawing of 100,000 things is listed in under 5 s and one more is refused. Golden: `tests/data/log/loss.json` (new section `losses`, parity wasm == native, plus `results` and `refused` cases of the arm).

Not built: the warning in the save chooser (arch-std-17 / arch-web-21); enhanced stereo, text runs and highlight (the document has no such feature yet: rows follow when it does); the independent check against the InChI of plan-03 (numbered follow-up in the PR); the explicit hydrogen count `h` of an atom and the scale of a molfile or CDXML (read to a bond length of 1) are not rows of the table.
