# Replay result `draw-result/1`, built

(plan-20; `crates/mzdraw/src/outcome.rs`, `replay.rs`; section "Replay result" of docs/mzdraw.md; schema `docs/schemas/draw-result-1.json`.) A replay request with `report`, `dry_run` or a non-empty `expect` is answered by one `draw-result/1` document, written by hand with the keys in a fixed order: `format`, `id` (the request's `id` or its index `n` in the batch; `replay_at(request, n)`), `ok`, `dry_run`, `patch` (not written yet), `out` (only when ok and not a dry run), `created` and `removed` (ids after minus before and before minus after, per kind, ascending), `failed` (`stage` `log`, `op` the 0-based index, `key`, `id`; `candidates` and `rows` are written when a later slice fills them) and `expect` (`check`, `ok`, `detail` per expectation). Arms of `expect`: `std` (`"none"`), `std_absent`, `pieces`, `smiles` (compared byte for byte with `Document::to_smiles()`, not canonicalised; `detail` gives the actual SMILES). An `out` the drawing cannot give is the keyed error (exit 2), dry run or not. The JSON Schema file is checked by hand in the tests (no validator dependency); its reserved stages and keys are never written yet. A refused op or a false expectation is a verdict (`ok:false`, nothing written; the example `replay` exits 1); an invalid request (unknown field or arm, op outside the table, malformed `id`) is still the keyed error (`error.draw2.requestField`, `error.draw2.expect`, `error.draw2.request`). Without the three fields the answer is the bare output and an op error stays an error. The `request` section of the table (`draw-edit-schema/1`, `schema::REQUEST`) has one row per request field and `expect` arm. Golden cases: `tests/data/log/result-envelope.json` (new section `results`, with parity wasm == native and the exit codes); tests: `crates/mzdraw/tests/outcome.rs` (property: created and removed equal the differences of the two documents, computed from the `mzdraw/1` texts of random logs). Not built: the stages `select`, `plan` and `grant` (the stage `command` is written by tp-01 for a refused editor command of `commands`: `failed.op` is its index; a malformed command, argument or item is still an invalid request, exit 2), the key `patch`, the request fields `goal` and `grant`, the `expect` arms `stereo`, `lossless` and `chain`, the `--arm report` of plan-19, the exit codes of `mzlab-cli` (mzLab), the RDKit comparison of `{"smiles"}`.
