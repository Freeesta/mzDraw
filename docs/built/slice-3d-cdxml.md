# Slice 3d, built (CDXML)

the XML form of ChemDraw files, written and read from the public CDX SDK documentation (`crates/mzdraw/src/cdxml.rs`; the pages read are the IUPAC copy of the SDK; no code of any other program), on a small XML reader of our own (`xml.rs`: element tree only, no DTD followed, no entity expanded beyond the five of XML and the numeric ones, depth and element count bounded). In: the nodes and bonds of every fragment (groups included) go through the same door as a molfile and a KET file; element nodes with charge, isotope and radical; a labelled node is an R group, an abbreviation of our table (the atoms of its inner fragment are not read: the label is kept) or, for any other label, element list or node type, a query atom; orders 1, 2, 3 and 1.5 (kekulised), any other order a query bond; solid and hashed wedges of both ends and wavy bonds; captions (style runs joined, one document text per line), `arrow` objects, line graphics with a head, plus symbols. Everything else (shapes, curves, brackets, orbitals, tables, spectra, embedded objects) is counted and said; colour and font tables and reaction schemes are passed over (they hold no content of their own). Out (`save("cdxml")`): one fragment in points, y down, 30 pt to the bond; hetero atoms with `Element`, `NumHydrogens` and a label; R groups as generic nicknames; wedges as `WedgeBegin` / `WedgedHashBegin` / `Wavy` from the narrow end; arrows as an `arrow` object plus the older line graphic that points at it, plus signs, texts. Not read: `NumHydrogens` (the valence rules decide), stereo attributes other than the wedges, bold and dashed displays, colours, fonts and text faces. Not confirmed on the pages read (marked in the module): the head of a line graphic is taken as the first point of its `BoundingBox`, and `ArrowheadHead="Full"` as a full head. Binary CDX is not read.
