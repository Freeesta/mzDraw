# Pathway layout on the page, and the Graphviz proof (tp-06), built

(`Editor::pathway_tree` in `crates/mzdraw/src/editor_edit.rs`; item `pathway.tree` in `context.rs`; schema `choices` in `settings.rs`; page: `web/palettes.js`, `web/mzdraw.js`, `web/lang/mzdraw.js`; tests `crates/mzdraw/tests/pathway_page.rs`, golden `tests/data/log/pathway-page.json`, three e2e steps in `tests/e2e.mjs`; proof `tools/fidelity/pathway.py` with `tools/fidelity/pathway_graphviz.reference.json`; screenshots `docs/screenshots/tp-06-*.png`.)

**Button.** "Arrange pathway" is in the objects palette (`command("pathway-tree")`) and on the canvas context menu (item `pathway.tree`, enabled when an arrow is anchored at both ends). Both run `Editor::pathway_tree`: the layout and operations of tp-05's `pathway:tree`, run as one undo step *without* the extra route follow of `Editor::run`, so the page's log is the tail of the replay log of `{"commands":[{"command":"pathway:tree"}]}` and the bytes are equal (e2e compares the document, the SVG and the log with the golden). No new operation, field or request row.

**Settings.** `pathway.dir` (`right`, `down`) and `pathway.order` (`id`, `mz`, `rt`) are in the schema as `"choices":[{"key","values","default"}]`; the settings panel paints a select for each and sets them with `set("pathway.<key>=<word>")`; the default is not written to the settings file. The four numbers were already there (tp-05). Note: `down` means towards lower y of the document, which the page draws upwards (tp-05's rule, shown in `tp-06-binary-tree-down.png`).

**Live line.** `draw2.say.pathway`: "Pathway arranged: 4 structures, 3 arrows, no gap widened." The numbers come from Rust (`Editor::said_params`, `state().say.params`); the catalog has the plural forms. A refusal shows its key's text (`error.draw2.schemeCycle`, `schemeEmpty`, ...) and changes nothing.

**Proof.** `python3 tools/fidelity/pathway.py` gives the 13 synthetic graphs to Graphviz `dot -Grankdir=LR -Tjson`: ranks from the distinct rounded x, crossings counted as proper intersections of straight segments between node positions. Result with dot 2.43.0 (2026-11-21): 13 of 13 pass, ranks equal on every tree, crossings 0 ours and 0 dot on every graph; the DAG has no rank difference. Without `dot` it prints `skipped: dot not installed` and exits 0.

**Not built.** The key binding and the entry in arch-std-06's command table (that slice is not on `main`; the keyboard route is the focused button and the context menu opened with the Menu key). The page's way to draw an anchored arrow (tp-02b, in review): the cycle of the e2e is opened from a synthetic file, not drawn by hand. The kill test (the owner's judgement of three pathways against their habit) is for the owner: screenshots are in `docs/screenshots/`. Moves of the selection only: the command lays out the whole pathway.
