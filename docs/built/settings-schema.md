# Settings, one schema

the numbers of the style are one table in Rust (`settings::FIELDS`: key, unit, bounds, accessors); the reader, the writer, the validation and the per-key setter `Style::set` all go through it, and `settings::schema_json()` gives it to any surface (`{"format", "presets", "colours", "fields": [{"key", "unit", "min", "max", "default"}]}`), so the CLI of mzLab can reuse it as it is. One setting is written `<section>.<key>=<value>` (`Editor::set("style.line_width=2")`, the shape of `--set`; the one section of this version is `style`: the fields, `colour`, `preset`); the replay request takes `"set": [...]`, applied after `"style"`, and gives the same bytes as the page. A value outside its bounds, a key that is none or a setting that is not of that shape is refused with its key (`error.draw2.styleValue`, `error.draw2.styleKey`, `error.draw2.set`) and changes nothing. On the page the fields under "Your own values" are built from the schema; "Save settings" downloads the file the module writes and "Open settings" gives a file to the module; the last style is kept in the browser. Not built: the templates, abbreviations, shortcuts and editor sections.
