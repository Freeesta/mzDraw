# What an import does not keep, on the CLI route (rdkit-compare 3a)

Found by the RDKit comparison (`docs/study/rdkit-compare.md` F2, as corrected in review): an enhanced-stereo group (CXSMILES `&n` / `on`, V3000 `MDLV30/STEABS`, `STERAC`, `STEREL`) is not kept by the drawing; the page says so under its import (`draw2.import.stereoGroups`), the CLI route said nothing. Rule 15: what the page says, the CLI says.

**The field.** A `draw-result/1` (`report`, `dry_run` or `expect` of a replay request) has the key `imported`, between `removed` and `lost`: `[{"key","n"}]`, the notes of `io::Imported::notes` of the start text (`import`) and the file (`import_base64`) whose count is above 0, in that order, written like `lost`. The computed layout (`draw2.import.placeholder`) is said by the page but is no loss, so it is not an item: a plain SMILES has no `imported` key and the existing golden envelopes keep their bytes. The other notes come along by the same door: query atoms and bonds, S-groups, skipped records, data and maps left, duplicate maps, a code page, a cut name, the TP-table notes. Code: `outcome::Outcome::imported`, `outcome::KEYS`, `replay::replay_with`; the key table `docs/schemas/draw-result-1.json` (`x-key-order` and the item schema), the schema row of `report` (`"out":"schema"`, `edit-schema.json` and `docs/mzdraw.md` re-blessed).

Kept or not: the pinned `mzlab-mol` (3783626) can carry the groups (`Mol::groups`, `StereoGroup { kind: Abs | And | Or, atoms }`; read from CXSMILES and V3000 collections, written as a CXSMILES tail and as V3000 `STEABS` / `STERAC` / `STEREL`); the drawing cannot yet (no field in `mzdraw/1`). Keeping and drawing them is the next slice (queue row "rdkit-compare: enhanced stereo", part 2).

Tests: `crates/mzdraw/tests/outcome.rs` `what_the_import_does_not_keep_is_in_imported_as_the_page_says_it` (an "and" group, two "or" groups in a dry run, the same items as the page's notes, nothing for a plain SMILES, the place of the key) and `every_golden_envelope_follows_the_key_table` (the new key in the table); golden cases in `tests/data/log/result-envelope.json` (CXSMILES, V3000 collection, dry run), wasm == native in `tests/parity.mjs`.

Not built: keeping the groups in the document and drawing their labels (`&1`, `or1`); a `loss:FORMAT` item (the group is gone before any format is written: it is an import note, not an export loss); the computed layout as an item.
