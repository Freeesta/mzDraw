# What an import does not keep, on the CLI route (rdkit-compare 3a)

Found by the RDKit comparison (`docs/study/rdkit-compare.md` F2, as corrected in review): an enhanced-stereo group (CXSMILES `&n` / `on`, V3000 `MDLV30/STEABS`, `STERAC`, `STEREL`) is not kept by the drawing; the page says so under its import (`draw2.import.stereoGroups`), the CLI route said nothing. Rule 15: what the page says, the CLI says.

**The field.** A `draw-result/1` (`report`, `dry_run` or `expect` of a replay request) has the key `imported`, between `removed` and `lost`: `[{"key","n"}]`, written like `lost`, made by `outcome::import_notes` from the notes of `io::Imported::notes` of the start text (`import`) and then the file (`import_base64`). A note whose number is 0 is left out; one key is one item, `n` the sum over the text and the file; the exception is `draw2.import.smilesLine`, one item per SMILES line that could not be read with `n` its 1-based line number (at most `io::MAX_SAID` = 10, the others counted by `draw2.import.smilesMore`). The key is additive: `draw-result/1` keeps its id, and the schema says that a consumer must accept keys it does not know. The computed layout (`draw2.import.placeholder`) is said by the page but is no loss, so it is not an item: a plain SMILES has no `imported` key and the existing golden envelopes keep their bytes. The other notes come along by the same door: query atoms and bonds, S-groups, skipped records, data and maps left, duplicate maps, a code page, a cut name, the TP-table notes. Code: `outcome::Outcome::imported`, `outcome::KEYS`, `replay::replay_with`; the key table `docs/schemas/draw-result-1.json` (`x-key-order` and the item schema), the schema row of `report` (`"out":"schema"`, `edit-schema.json` and `docs/mzdraw.md` re-blessed).

Kept or not: the pinned `mzlab-mol` (3783626) can carry the groups (`Mol::groups`, `StereoGroup { kind: Abs | And | Or, atoms }`; read from CXSMILES and V3000 collections, written as a CXSMILES tail and as V3000 `STEABS` / `STERAC` / `STEREL`); the drawing cannot yet (no field in `mzdraw/1`). Keeping and drawing them is the next slice (queue row "rdkit-compare: enhanced stereo", part 2).

Tests: `crates/mzdraw/tests/outcome.rs` `what_the_import_does_not_keep_is_in_imported_as_the_page_says_it` (an "and" group, two "or" groups in a dry run, the same items as the page's notes, nothing for a plain SMILES, the place of the key), `every_kind_of_import_note_comes_through_and_one_key_is_one_item` (query atoms, a query bond and S-groups of a molfile; skipped records of a long SDF; the text and a PDF file together; the merge of one key and the line numbers of `smilesLine`; unreadable SMILES lines) and `every_golden_envelope_follows_the_key_table` (the key in the table, and every item of `imported`: `{key, n}` in that order and nothing else, a key of the import notes, `n` from 1, one item per key but `smilesLine`); golden cases in `tests/data/log/result-envelope.json` (CXSMILES, V3000 collection, a CXSMILES dry run, a query molfile, text and file together), wasm == native in `tests/parity.mjs`.

Not built: keeping the groups in the document and drawing their labels (`&1`, `or1`); a `loss:FORMAT` item (the group is gone before any format is written: it is an import note, not an export loss); the computed layout as an item.
