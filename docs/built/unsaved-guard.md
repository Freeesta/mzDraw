# Unsaved-changes guard (unsaved-guard), built

**Saved point (Rust, `Session::dirty`, `Editor::dirty`).** The history keeps the number of applied steps at the last save, export, open or new (`saved`). The drawing is dirty exactly when the applied steps are not that many, so undoing back to the saved point makes it clean again and redoing past it makes it dirty again. A new step made after undoing past the point, or a step that grows in place (repeated nudges are one step), makes the point unreachable: the drawing stays dirty. It counts steps, not bytes, so it is deterministic and exact. A start text or file (`import`, Restore, `open`) and `new` are saved points. **Only the native document is loss-free, so only writing it is a saved point** (`Editor::exported`, decided in Rust): the page tells the module which kind it wrote (`mark_saved(kind)`), and a molfile, SMILES, SVG, PNG, PDF or any other export leaves the drawing dirty. The command `save` takes an optional `format` with the same rule (no format is the native document). The question's Save always writes the native document (`unsaved_format`), whatever the default export is; the toolbar Save button writes the default export and so marks the drawing saved only when that is the native document.

**What asks.** `Editor::unsaved` is dirty and not empty (an empty canvas has nothing to lose, so it never asks); `Editor::guard` is `Ask` then, `Go` otherwise. `Choice` says what each answer does: Save (write the file, then go on), Don't save (go on), Cancel (nothing). The page asks the module (`unsaved_guard`, `unsaved_choice`) and only shows the question.

**State and results.** `state()` has `dirty` and `unsaved`. The `draw-result/1` document of a replay always has `dirty` (after `changed`, before `orient`); the 22 golden files of `tests/data/log/` that hold such a document were re-blessed for that one key and nothing else (checked: each differs from `main` by the `dirty` key only), and `edit-schema.json` for the new rows.

**CLI twin (rule 15).** Request commands `new` (`discard`), `open` (`text`, `discard`) and `save`: `new` and `open` on a dirty, non-empty drawing are refused with `error.draw2.unsaved`: without `report`, `dry_run` or `expect` the replay returns that keyed error; with one of them it returns a `draw-result/1` verdict with `ok` false, `failed` `{"stage":"command","op":INDEX,"key":"error.draw2.unsaved","id":0}` and `dirty` true. The exit code and the stdout/stderr split are those of `mzlab-cli mol draw`: not verified here, mzLab side. The refusal is lifted when `discard` is true or a `save` of the native document came first; a start text is clean. Rows in the request table (`docs/mzdraw.md`, the schema golden), cases in `tests/data/log/unsaved.json`, parity wasm == native by `tests/parity.mjs`.

**The page.** File group: New (`clear`) asks first when the drawing holds unsaved work; the drawing is then emptied by `new_drawing` (one undo step, so Undo still brings it back), and the Restore of a saved drawing (which replaces what was drawn while the offer waited) asks the same way. Closing or reloading the tab shows the browser's own prompt only when `unsaved_guard` says `ask` (`beforeunload`). The question is the alert dialog `#d2-unsaved` (`web/unsaved.js`): `role="alertdialog"`, `aria-modal`, labelled and described, Save has the focus, Tab and Shift+Tab stay inside (a focus that leaves is brought back), the rest of the page is `inert` while it is open, only one question can be open (a second action asked for meanwhile does nothing), Escape is Cancel, Enter presses the focused button, the focus goes back to where it was (the canvas when that button is gone), buttons of 44 px, mouse, keyboard, touch and pen. Texts: `draw2.unsaved.*` and `error.draw2.unsaved` in `web/lang/mzdraw.js`. Tests: `crates/mzdraw/tests/unsaved.rs`, the golden cases, and the e2e step "the unsaved-changes guard" (mouse, keyboard, touch, pen; screenshots in light and dark at device scale factor 2: `docs/screenshots/unsaved-guard-light.png`, `unsaved-guard-dark.png`). The steps of `tests/e2e.mjs` that press New on a drawing now choose "Don't save" in the shared helper `tool`, keeping what they assert.

Not built: "Open a file" and the Add field only add a structure to the drawing (nothing is replaced, so nothing asks); there is no template or example library yet whose loading would replace the drawing; the CLI `open` reads a saved document only (other formats are the start `import`); the guard does not look at the style or the settings, only at the drawing; a download cannot be confirmed by the page, so the saved point is set when the native document is handed to the browser.
