# Engine glue callable natively, built

(plan-04): `crates/mzdraw-wasm/src/glue.rs` (feature `mzlab`) is the one place that calls the engines of mzLab (`mzlab_feat::chem`); `lib.rs` no longer does. `glue::check(&Document)` is the old `check/1` call moved unchanged (the golden outputs did not move), `glue::run(engine, &doc, args)` builds the molfile of the document once (`to_molfile_for_check`, atoms in pool order) and calls `check`, `cip`, `cut`, `mech`, `hilite` or `sel` with `args` (a JSON object of the engine's own fields) merged with the `molfile`, giving the engine's JSON byte for byte; an engine not in the build, or a name that is none, is `error.draw2.engineMissing`. `glue::ids(&doc)` maps an engine atom number (0-based, molfile order) to the document id: after deletions the ids are not `0..n`, so an answer is never read as an id directly. The headless door `glue::replay` takes the replay request plus `"engines":[{"engine","args"}]` and gives `{"engines":[{"engine","answer"}|{"engine","error"}]}` in request order; the CLI twin is `cargo run -p mzdraw-wasm --example replay_glue < request.json` (exit 2 with the keyed error on stderr for a missing engine), the `.wasm` export is `replay_glue`, and `tests/parity.mjs` compares the bytes of both for each of the six engines. The features `hilite` (mzlab-feat `sub`) and `sel` (mzlab-feat `sel`) of the bridge are on by default; the module grew from 592,912 B to 739,519 B (cip, cut and mech together +102.8 kB, hilite +38.0 kB, sel +11.4 kB). Not built: painting any engine answer (each feature slice paints its own), an in-process comparison with `mzlab-cli` (the CLI is not a dependency of this repository; both call the same `*_json` functions on the same molfile, compared in `crates/mzdraw-wasm/tests/glue.rs`).
