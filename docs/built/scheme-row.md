# One-line scheme layout, built

(plan-13; `crates/mzdraw/src/scheme.rs`, the command `scheme:row` in `commands.rs`, `Editor::scheme_row` and `scheme_row_with`, the shared role rule `rxn::role` / `rxn::along`; tests `crates/mzdraw/tests/scheme.rs`, golden cases `tests/data/log/scheme-row.json`, independent check `tools/scheme_row/rdkit_roles.py` with its output `tests/data/scheme_row/reference.json`; screenshots `docs/shots/plan-13-scheme-row*.png`.)

`scheme::row(doc, style, opts)` gives `move` operations (and one `obj.set` of the head of each free arrow) that put the structures (connected pieces), arrows, plus signs and texts of a drawing, or of the selection, on one baseline: equal gaps of `gap` bond lengths (default 1.0, above 0), each structure's box (`route::structure_box`, labels included) centred on the line, each plus sign in a slot of 0.5 of its own, each arrow as long as its notes ask (widest note or own text plus 0.5 at each end, at least 2.0), and `wrap` (bond lengths, default 0: never) breaking the row after the first arrow that ends past that width, the next line under the first and starting at the same end. The main direction is the way the first arrow points (left to right when there is none); the order is by line (units whose vertical reaches overlap are one line, so a wrapped row is read line after line) and then by centre along the direction. One undo step; the log carries `move` and `obj.set`, no new operation.

Roles. One rule with `rxn::to_rxn`: `rxn::along` and `rxn::role` (before the tail reactant, past the head product, alongside agent) are the functions both use. In a drawing with exactly one arrow and no `wrap`, a structure between tail and head is an agent at any distance (a far agent is brought next to the arrow and stays an agent). Where there are several arrows or a `wrap`, a structure counts as an agent (a note) of an arrow only within 3 bond lengths of it (`NOTE_REACH`), as a text always does, because the reaction file has one arrow only and lines of a scheme stand under one another; wrapped lines are kept at least 3.1 bond lengths apart so a second `scheme:row` reads the same notes. The notes (texts within reach, agent structures) are stacked above or below the arrow by where they stand now, centred on it. The baseline is the first arrow's line. A second `scheme:row` gives no operation (a thing within 5e-5 of its place is not moved; ties of the fifth decimal go one way).

Exactness. Coordinates are stored to four decimals, so a thing lands within 5e-5 of its ideal place on each axis and every gap or centring is exact within 1e-4 (+1e-9 of float noise): `BOUND` in the tests, derived there. The property test runs 60 seeded synthetic schemes in five modes (one and two steps, right to left, wrapped, wrapped right to left) and checks: no overlap, order kept, equal gaps, structures and plus signs on their line, notes inside the arrow and off its line, every line starting at the same end, undo identical, second row empty, and the file roles of one-arrow schemes unchanged. A selection is checked to leave everything outside it untouched and to give what laying out a drawing of only the selection gives.

Anchors (E27): an arrow with both `from` and `to` gets no end set; its structures move and `route::route` gives its ends (the tail of the operation list is that route). An arrow with only one anchor is laid out as a free arrow. A zero-length arrow is laid out as a level arrow of the least length. The argument `gap` is not tp-05's `pathway.col_gap`.

CLI: `{"command":"scheme:row","args":{"gap":1,"wrap":0,"atoms":[],"objects":[]}}` (or in `commands`, with `report`, `dry_run` and `expect` as for the other commands: a golden `results` case); `atoms` and `objects` are the selection, absent means everything; a bad `gap`, `wrap` or an unknown key is `error.draw2.request`, an atom or object the drawing does not have is `error.draw2.noAtom` / `error.draw2.noObject` (stage `command`). Like `move` and `rotate`, the keys of `args` are described in the text of the `args` row of the request table, not as rows of their own. Page: the button `scheme-row` of the objects palette (`command("scheme-row")`), the selection or everything, default gap, no wrap; when nothing would move the status line says "The scheme is already laid out." The page, the replay request and the log of the page give the same bytes, tested for the plain scheme, an anchored arrow, a selection and a wrap (`scheme_row_with`).

Independent check. `tools/scheme_row/rdkit_roles.py` writes the one-arrow cases as RXN before and after, reads both with RDKit (2026.09.2, 2026-11-21) and compares reactants, products and agents by canonical SMILES: the four one-arrow cases agree (`tests/data/scheme_row/reference.json`; exit 3 when RDKit is missing). It says that the roles a second program reads did not change; it does not say the layout is right.

Not built: orienting cores (plan-14); catalytic cycles; several rows with branching arrows; a main direction other than horizontal (arrows are made level); the roles of a wrapped drawing in a reaction file (it has several arrows); a `gap` or `wrap` entry on the button; the velocity count of "two-component reaction" before and after.
