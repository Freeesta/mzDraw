# TP table and step field hardening (tp-hardening), built

(`crates/mzdraw/src/tptable.rs` (`guards`, `unguard`, the comments), `tp_list.rs` (the unguard on import, unit tests), `editor_tools.rs` (Ctrl+Alt in the open step field), `web/lang/mzdraw.js` (`tpGuard`, `tpMass`), `crates/mzdraw/tests/tptable.rs`, `step_field.rs`, `feedback.rs`, `crates/mzdraw-wasm/tests/tptable.rs`, golden cases `tests/data/log/tp-table.json` (two new). No `draw_edit/1` op, request field or request row is new: the CSV is an output and its import is the import of a list, so the CLI route is the one that already exists (`out tptable-csv`, `tp:import`), and the parity golden replays it natively and in the `.wasm`.)

Follow-ups of tp-09 and tp-11, closed in one slice.

1. **The CSV guard is injective.** The writer put a `'` before a text cell that starts with `=`, `+`, `-` or `@`; the reader took a `'` off before those characters, so a cell that really was `'=x` and a guarded `=x` were the same text, and an `mz_obs` or `rt` that was not a number was guarded on export and never unguarded. The rule, decided in Rust (`tptable::guards`, `unguard`): a cell that starts with `=`, `+`, `-`, `@` **or `'`** gets one more `'`; the import takes one `'` off when one of those five characters follows. So `=x` is `'=x`, `'=x` is `''=x`, `'a` is `''a`, and a hand-made `'a` (nothing of the five follows) is read as written. Every text cell of the table (`tp_id`, `parent_id`, `adduct`, `mz_obs`, `rt`, `level`, `identifier`) comes back as it was, with commas, quotes, line breaks; two things are outside the round trip and said so: edge white space (the importer trims it, as it always did) and `;` in a `parent_id` (the separator of parents). The guard against a formula is kept. Proof: `tp_list::tests` (a property test of 3000 pseudo-random synthetic cells, written then read, and the pairs that failed before, with a mutation check: without the new character both fail), golden cases `tp-table.json` 8 and 9 (a list with names such as `'=x`, `''y`, `+z`, `-m`, `@w` exported; that export imported and exported again is the same bytes, asserted in `crates/mzdraw-wasm/tests/tptable.rs`). The count `tpGuard` now includes the cells that start with `'`; its text on the page says so.
2. **Drifting comments**, listed in the PR text and fixed: the header of `tptable.rs` said the guard covers the five text columns (the code also guards `mz_obs` and `rt` when they are not a number); said the importer undoes the guard (it did, for four columns only, not for `mz_obs` or `rt`); the paragraph "Reading it back" named three columns of the seven the importer reads; the `NOTE_KEYS` doc did not say the ninth key is the CSV's alone (the JSON schema lists eight); `csv_counted` described the importer. In `tp-09-tp-table.md`: the `tpMass` text and note said "more than 200 atoms" (the engine reads a structure of 1000 atoms or more as nothing, `error.draw2.valuesZero`; 200 is the structure cap of the live panel); the cost paragraph said best of 5 and "8 times plus a few ms" for a test that takes the least thread CPU time of 7 and bounds the ratio by 6; the counts of tests and golden cases. No behaviour change in this item (the text of two page messages apart).
3. **A structure above 500 atoms.** It already had an empty `smiles` cell and a keyed note `draw2.export.tpSmiles` (JSON `notes`, `lost` of the result, the words on the page), with no test. Now `a_structure_above_the_smiles_cap_has_an_empty_cell_and_a_keyed_note` fails if the note or the empty cell changes, for the JSON and for the CSV, and checks the detail key `error.draw2.smilesSize`. The CSV itself carries no notes (it is a table); they are in `lost` and on the page, and a CLI caller reads them in the `draw-result/1`.
4. **Step field.** Tests for the cut of `step_text` at 64 characters (characters, not bytes) and for Ctrl+Alt+Z / A / D / Y typed in the open field. The second test found that those four keys reached the drawing's shortcuts from inside the input (Ctrl+Alt+Z undid the drawing; Ctrl+Alt+Y redid it): the page sends Ctrl+Alt keys to the module, and the module only treated `[` `]` `{` `}` as the field's. Fixed in `key_inner`: with the field open any other Ctrl+Alt key returns 0 (the browser has it); with the field closed nothing changes. The element arithmetic of `step_masses` (seven engine calls, then kept) is written in `tp-11-step-field.md` and tested with a stand-in engine.
5. **`tests/feedback.rs`** builds the repository part of the expected URL from `brand::REPOSITORY`.
