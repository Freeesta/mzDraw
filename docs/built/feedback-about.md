# Report a bug / suggest an improvement, and About (feedback-about), built

(`crates/mzdraw/src/feedback.rs` (the report, `feedback/1`, and `about/1`), `brand.rs` (`VERSION`), `replay.rs` (request field `feedback`), `schema.rs` (one request row), `crates/mzdraw-wasm/src/lib.rs` (`feedback`, `about`), page `web/feedback.js`, `web/index.html` (`#d2-meta`, `#d2-report`, `#d2-about`), `web/mzdraw.css`, `web/lang/mzdraw.js` (`draw2.about*`, `draw2.report*`, `feedback.*`, `error.draw2.feedback*`), `.github/ISSUE_TEMPLATE/{bug,improvement,config}.yml`; tests `crates/mzdraw/tests/feedback.rs`, golden cases `tests/data/log/feedback.json` (new section `feedbacks`, held wasm == native by `tests/parity.mjs`), four steps of `tests/e2e.mjs`; screenshots at deviceScaleFactor 2 in `docs/shots/feedback-*.png`.)

**What it is.** (The improvement form carries the label `enhancement`, which the repository has; the bug form `bug`.) Two small buttons at the bottom of the canvas, "About" and "Report a bug / suggest an improvement", open two popovers (no modal dialog). The report box chooses Bug or Improvement and has a box "Include the command log of my drawing. It will be visible publicly on GitHub." that is OFF by default. "Open on GitHub" opens, in a new tab (a link with `rel="noopener noreferrer"`), a new issue of the repository from the form `.github/ISSUE_TEMPLATE/<kind>.yml`, prefilled. The site has no server and the page sends nothing: no backend, no tracker, no request of its own to GitHub (the e2e watches the page's requests). Nothing leaves the browser until the person submits the issue on GitHub; the About text and the tooltip of the button say so. About shows the name (`mzdraw::NAME` through the catalog key `draw2.name`), one sentence, the version (`mzdraw::VERSION`), the links to the repository and the licence, the privacy sentence ("once the page is loaded it works offline and sends nothing": offline after loading, there is no service worker) and the report button.

**What the URL holds** (all made in Rust, `feedback::build`; the page only opens it). `template` (the form), `title` (`Bug:` or `Improvement:`), `page` (the field of the form: version, the browser's user agent, language) and, only if the box is ticked and the whole URL stays at or under 6000 bytes, `log` (the command log `draw_edit/1` of the drawing). GitHub fills a form field from the query parameter of its id and ignores `body` for a form, so the URL carries the field ids; `body` of the answer is the same text as plain Markdown (for the clipboard and the CLI). Every refusal has a key: `feedback.logTooLong` (the log is left out, the page offers "Copy the log" to the clipboard) and `feedback.noLog` (asked for, but the drawing has no operation). Structures are never in the report except through a log the person ticked. Text is percent-encoded as UTF-8 (`&`, `#`, `=`, `+`, spaces and line breaks are safe).

**CLI twin (rule 15).** Request field `feedback` of `mzlab-cli mol draw` / `replay`: `"bug"`, `"improvement"`, or `{"kind", "log", "agent", "lang"}`; the answer is `feedback/1` JSON `{format, url, template, title, body, truncated, notes}`, deterministic (no time, no random); `agent` and `lang` are empty from the CLI. It stands alone like `values` (`error.draw2.feedbackAlone`); another kind is `error.draw2.feedback`. One row in `schema.rs` (`edit-schema.json` and the table of `docs/mzdraw.md` move by that row only). The log comes from the same `Session` that the page's call uses.

**Proof.** Unit (6): escaping of unicode, newline, `&`, `#`, `=`, `+`; the form and title per kind; the log off by default and never silent; the 6000-byte limit (a log that fits, one that does not, line breaks counted as three bytes); the request field gives the same bytes as the page call and its refusals; About. Six golden cases. e2e (4 steps): keyboard (arrows choose, Space ticks, Enter opens, Escape closes and gives the focus back), too-long log and "Copy the log" (the clipboard holds the log), About, touch (44 px targets) and pen; the new tab is intercepted, the URL is parsed and checked, and the page makes no request to GitHub.

**Not built.** A text in another language (English only); any server side, any reading of the issue by the page; the screenshots of the report box on a phone.
