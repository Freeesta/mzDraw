# Text panel: edit and style the text on the canvas, built

A text object can be selected, edited in place and styled by part, like a small word processor: bold, italic, underline, subscript, superscript, font, size, colour and line breaks. Select some of the characters, press a style, and only those characters change. Every change is an `obj.set` of `draw_edit/1` (`runs` or a plain `text`), so it undoes exactly and replays natively; the panel adds no operation and no field to the document (it builds on `text-runs.md`).

Code: `crates/mzdraw/src/textedit.rs` (the range logic), `editor_text.rs` (the selection, the keys, the pointer, the panel state), `scene.rs` (the selection band and the caret), `prefs.rs` (`text.font`, `text.size`), `web/index.html`, `web/mzdraw.js`, `web/mzdraw.css`, `web/lang/mzdraw.js` (the panel). Tests: the unit tests of `textedit.rs`, `crates/mzdraw/tests/text_panel.rs`, golden cases `tests/data/log/text-panel.json`, the e2e steps "text panel by keyboard / mouse / touch / pen" and "text preferences" of `tests/e2e.mjs`.

## How it works

- **A selection inside a text** is the user's view, kept in the editor (`Overlay::text`: the object, the anchor and the caret as character positions in the plain text, a line break counting as one). It is no step of the history. A text that is the whole selection shows the panel and the range is all of it; while it is edited the range is what is selected.
- **Entering and leaving.** Select a text with the Select tool, then Enter, F2, the panel's *Edit text* button or a double click (double tap) on it. The caret goes to the end (a double click selects the word). Escape stops editing and leaves the text selected; Escape again clears the selection. A press outside the text ends the editing and goes on as any press.
- **Keys while editing** (decided in Rust, `Editor::text_key`): characters, Enter (a line break), Backspace, Delete, Left and Right, Up and Down (by line), Home and End (of the line), each with Shift to grow the range from the anchor; Ctrl/Cmd+A selects the text; **Ctrl/Cmd+B, I, U** toggle bold, italic and underline; **Ctrl/Cmd+,** and **Ctrl/Cmd+.** toggle subscript and superscript. These keys do not clash with the command table: Ctrl+Z, Y, D and the clipboard keep their bindings, and outside the editing Ctrl+B, I, U, comma and period are not bound. The page forwards each key to the module; a field that takes no look (`#d2-text-input`) holds the keyboard focus while a text is edited, for input methods and the keyboards of phones, and forwards what they type (`text_input`).
- **Pointer, touch and pen** (the same pointer events as every tool): a press inside an edited text puts the caret at the nearest boundary between two characters (`textedit::pos_at`, from the one table of advance widths), Shift+press extends the range, a drag grows it. Touch and pen need no hover: the *Edit text* button replaces the double click.
- **The style buttons** (`Editor::text_style`: `b`, `i`, `u`, `sub`, `sup`, `font`, `size`, `colour`): over a range, the change applies to the range only. A toggle over a mixed range turns the property on for all of it, and the next press turns it off (as in a word processor); sub and sup exclude each other. With a caret and no range the button sets the style of the next typed characters (it is shown pressed; nothing is written yet). A selected text that is not edited is styled as a whole. Neighbouring runs of one style merge (`runs::canon`), so equal texts have equal bytes, and a text left with no style is a plain `text` again.
- **Typing and deleting** (`textedit::splice`): the typed characters take the style of the character before the caret (or the range's first character); they join the undo step of the characters typed just before them while nothing came between (a move, a style change or an undo ends the run); in the log every character is still its own `obj.set`. What does not fit the caps of a text (1000 characters, 20 lines, 400 runs) is cut off the end of what is typed, and a text at its cap says `error.draw2.runsCount`; styling never changes the length. A text emptied by deletion is removed with its object in the same step (undo brings it back).
- **The colour** is the colour flyout's palette (`ink::PALETTE`, each colour with its name as text, Automatic first): the panel's *Text colour* button opens it; the existing `Editor::colour` colours the range while a text is edited (`selection_colour` says the range's colour, so the colour in use is pressed there too) and the object when it is only selected, as before.
- **A refusal that writes nothing** (a paste of control characters only, `error.draw2.textChars`; a cap, `error.draw2.runsCount`; a toggle that would pass 400 runs, `error.draw2.runsCount`) changes neither the text nor the history, and keeps the range.
- **The panel** (`state().text`, `Editor::text_json`; it also says what to show: `fontKey`, `fontExtra` for a mixed or outside font, the `sizes` list with the size in use, and the `range` kind, so the page only paints): `null` when no text is selected, else the object, whether it is edited, the range, the length, the style under the range (`true`/`false` for each of b, i, u, sub, sup, `null` where the range is mixed; the font, the size in percent and the colour likewise), the lists of the controls (`fonts`: key and family; `sizes`: percent) and the cap. The page decides nothing: it shows `aria-pressed` as `true`, `false` or `mixed`, selects the font and size, adds a disabled entry for a value outside the list (a font of a file, a size between two) and says the range in a status line (`Text: 5 of 11 characters selected.`). Controls are 36 px or more (44 px on a coarse pointer); Escape closes the colour list.
- **Fonts**: `textedit::FONTS` (its keys are `FONT_KEYS`, the words of `text.font`; a test ties the two, the sizes `SIZES` and `SIZE_WORDS`, and that every family and size passes `runs::check`) (Arial, Helvetica, Times New Roman, Courier New, Georgia, Verdana, and the font of the drawing's style). This is the list of the panel and of the preference, not a limit of the document: a run may carry any family `runs::check` accepts, and one outside the list is kept as written. Sizes are 50 to 400 percent of the style's size (`sz` 0.5 to 4).
- **Visible characters**: moving with Left/Right, Backspace, Delete and a pointer press go by clusters, not code points: a zero-width joiner (and the character it joins), a variation selector, a combining mark and an emoji skin-tone modifier stay with their base, so Backspace on a joined emoji removes it whole and leaves no dangling joiner. No new dependency; the rule is `textedit::extends`. Limit: two regional indicators (a flag) and other grapheme rules (Hangul jamo, Indic conjuncts) are not joined, so Backspace removes one code point of them.
- **Display**: the selected range is a band of the selection token behind the text, one per line, and the caret a line of the focus token (not blinking, so nothing flickers for people who need still screens); neither is part of an export. The hit test of a text now uses its drawn width and lines (a formatted or several-line text is hit where it is drawn).

## Preferences: a Text group

`text.font` (`default`, `arial`, `helvetica`, `times`, `courier`, `georgia`, `verdana`) and `text.size` (percent of the style's size: 50, 75, 100, 125, 150, 200, 300, 400) are settings like the others (`<section>.<key>=<value>`, the `--set` shape; rows in `schema.rs`; the group `text` of the Preferences panel, built from the schema; reset per group). They live in the object `text` of the settings file `mzdraw-settings/1`, written only when not the defaults; keys of `text` this version does not know are kept and written back, and a stored file with a `text` object it cannot read loses only that object (the note `error.draw2.textPref`). A new text made by the text tool gets runs with the family and the multiple of the size; with the defaults a new text is plain, so every earlier log is unchanged. A value outside the lists is `error.draw2.textPref`.

## CLI route (rules 10 and 15)

The panel emits nothing the log does not already know: bold on a range is `{"op":"obj.set","id":8,"runs":[{"t":"Pd","b":true},{"t":"(OAc)"}]}`, typing is `obj.set` with the new runs (or a plain `text` when no style is left), removing the last character is `remove`. `tests/data/log/text-panel.json` holds two cases of such logs (ranges styled, text typed and restyled, a line added, text removed), the five refused requests, and the settings file with and without the `text` object; the page and the native replay give the same bytes (`tests/parity.mjs`), and `crates/mzdraw/tests/text_panel.rs` replays the log of a panel session on the start document to the same document as the editor holds. The preferences are `--set text.font=times --set text.size=150`.

## Not built

- Lists, alignment, tables, images in a text, fonts outside the list of the panel (a file's font is kept, not chosen).
- Styling the text of an arrow in place (the panel acts on text objects; an arrow's text is set by `obj.set` as before). With an arrow selected alone, F2 says so with the keyed note `error.draw2.textArrow` (shown like every refusal); the panel does not appear for an arrow.
- Ctrl+arrow by word, a selection by triple click, rich-text paste (a paste into an edited text is plain text; copy and cut give the plain text of the range).
- Underline in KET and the fonts of the PDF stay as `text-runs.md` says.
