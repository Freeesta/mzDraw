# arch-std-22, built (read binary CDX)

The binary file of ChemDraw (`VjCD0100`), read from the public CDX SDK pages (the IUPAC copy: format overview, data types, object and property pages; no code of any other program).

- `crates/mzdraw/src/cdx.rs`: the reader. It walks the tagged items (header of 28 bytes; objects with bit 15 of the tag set, a 4-byte id and a closing `00 00`; properties with a 2-byte length, or `FFFF` and a 4-byte length) and builds the same element tree the CDXML reader works on, with the CDXML names and attribute strings (coordinates from 1/65536 pt, y-then-x pairs turned to x-then-y, enumerations as names, bond order bits as names). `cdxml::from_tree` is the one mapping for both forms (`from_cdxml` is now parse + `from_tree`): fragments, nodes, bonds, wedges, captions, arrows, plus signs, R groups and abbreviations come with it, and everything else is counted in the notes as for CDXML. An object of an unlisted tag is kept as an element the mapping counts; a property of an unlisted tag, or of a size the pages do not give it, is skipped by its length. A file with no document object around its objects (the example of the overview page is one) is read as the content of one.
- Bounds: every length is checked against the file (no allocation by a declared length), depth is `xml::MAX_DEPTH`, objects (and text runs) `xml::MAX_ELEMENTS`; a file cut at any point, with a stray end, a property outside an object, or a second document is refused with `error.draw2.cdx`. Nothing is read in part: a refused file adds nothing.
- Content sniffing: `io::import_bytes` finds `VjCD0100` first (format `cdx`). The page opens it through the same file chooser (`.cdx` accepted); the paste of text is unchanged (the clipboard carries no CDX in the browser).
- Replay (the route of `mzlab-cli mol draw`): the request has a new field `import_base64`, the bytes of a file (a CDX, or a PNG saved by mzDraw) in base64, read after `import`. Golden cases: `tests/data/log/cdx.json` (two files, three refused requests); `tests/parity.mjs` holds the module to the native bytes. The request section of the table of plan-01 (`schema.rs`) does not exist yet, so this field has no row there: it goes in when that section lands.
- Tests: `crates/mzdraw/tests/cdx.rs`. A small CDX writer lives in the test only; for each CDXML fixture of `tests/cdxml.rs` (shared now: `tests/data/foreign.cdxml`) the CDX it makes opens to the same document and notes as the CDXML; the one example the overview page prints byte by byte is read as printed; every cut of two synthetic files is refused; random corruption is never a panic; bounds, unknown items, text code pages. e2e: a `.cdx` opened by keyboard (focus on Open, Enter) and by touch (tap), and a cut one refused in words.

Not built: writing CDX; CDX inside Office documents; the Windows clipboard. Not read: arrowhead properties (`ArrowHeadHead` and the other arrowhead pages were not available; the arrow ends come from `Tail3D` / `Head3D`), colours, font faces and sizes, `NumHydrogens`, objects other than the ones CDXML reads (counted). Chosen where the pages are silent: text is decoded as UTF-8 when the font of its run has code page 65001 and as Latin-1 otherwise (the list of code pages is on a page that was not found). The proof against Open Babel (E17 of the backlog) is not made: not measured.
