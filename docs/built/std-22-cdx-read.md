# arch-std-22, built (read binary CDX)

The binary file of ChemDraw (`VjCD0100`), read from the public CDX SDK pages (the IUPAC copy, https://chemapps.stolaf.edu/iupac/cdx/sdk/; no code of any other program).

## What it does
- `crates/mzdraw/src/cdx.rs` walks the tagged items (header of 28 bytes; objects with bit 15 of the tag set, a 4-byte id and a closing `00 00`; properties with a 2-byte length, or `FFFF` and a 4-byte length) and builds the same element tree the CDXML reader works on, with the CDXML names and attribute strings (coordinates from 1/65536 pt, y-then-x pairs turned to x-then-y, enumerations as names, bond-order bits as names). `cdxml::from_tree` is the one mapping for both forms: fragments, nodes, bonds, wedges, captions, arrows, plus signs, R groups and abbreviations come with it, and every other object is counted in the notes as for CDXML.
- Sniffing: `io::import_bytes` finds `VjCD0100` (format `cdx`). The page opens it through the file chooser (`.cdx` accepted); paste of text is unchanged (the browser clipboard carries no CDX).
- Replay (the route of `mzlab-cli mol draw`): the request field `import_base64` is the bytes of a file (a CDX, or a PNG or a PDF saved by mzDraw) in base64, read after `import`. It has its row in the `request` section of the table (`schema.rs`, `docs/mzdraw.md`).

## Bounds and what is refused (error `error.draw2.cdx`, nothing is read in part)
Every length is checked against the file (no allocation by a declared length); depth is `xml::MAX_DEPTH`; objects and text runs together `xml::MAX_ELEMENTS`, checked before the runs are built. Refused: a file cut at any point; a stray end; a property outside an object; a second document; a known property of a size the pages do not give (an element number of 3 bytes ...); a text whose first run does not start at 0, whose run starts decrease or lie beyond the text (the runs cut disjoint pieces of the text, so decoding never costs more than the file holds); anything after the end of the document except the 2-byte end mark of the file. A file with no document object around its objects (the example of the overview page is one) is read as the content of one and needs the end mark.
Said, not refused: an object of a tag the pages list that CDXML does not read, or of an unlisted tag, is counted in `info.other` (note "things mzDraw does not draw"); an unlisted property is skipped by its length and counted in `info.props_skipped` (kept out of the page note: every ChemDraw file holds dozens of style properties); a text run in a code page other than 65001 (UTF-8), 1252, 28591 or 0 is read as Latin-1 and counted in `info.code_page_runs`, which the page says ("draw2.import.codePage").

## Tag tables checked against the SDK pages
Objects: `AllCDXObjects.htm`, every value of the table in `cdx.rs` (`object_name`: 0x8000 to 0x8027, including Arrow 0x8027, Border 0x8020, Geometry 0x8021) compared by a script with the page. Properties: `TableOfProperties.htm` (tag, name and type of 0x0012, 0x0100, 0x0200, 0x0204, 0x0207 3DHead, 0x0208 3DTail, 0x0400, 0x0402, 0x0420, 0x0421, 0x0422, 0x0600, 0x0601, 0x0604, 0x0605, 0x0700, 0x0A00, 0x0A02, 0x0A07). Enumerations: the pages `properties/Node_Type.htm` (0 to 10), `Bond_Display.htm` (0 to 14), `Bond_Order.htm` (bits), `Graphic_Type.htm` (0 to 7), `Arrow_Type.htm` (0 to 128), `Symbol_Type.htm` (0 to 13; value 13 is a second LonePair, drawn as a bar, as the page says), `Atom_Charge.htm`, `Atom_Radical.htm`. Data types: `IntroCDX.htm`, `DataType/CDXCoordinates.htm`, `CDXString.htm`, `CDXNumeric.htm`, `CDXObjectID.htm`, `CDXFontTable.htm`. The one example printed byte by byte (`IntroExampleSimple.htm`) is also read as printed by a test. The test writer keeps its own copy of the tables, so round trips alone would not catch a wrong value; the pages and the printed example do.
Unverified: the list of code pages (the page of the CDXML `charset` property was not found; 1252 and 28591 are the Windows and ISO numbers, 65001 UTF-8, and the font table example shows 0x04E4 = 1252); the arrowhead properties (`ArrowHeadHead` page not available: not read); node types above 10 (not on the page read).

## Tests
`crates/mzdraw/tests/cdx.rs`: a small CDX writer lives in the test only; each CDXML fixture of `tests/cdxml.rs` (the foreign file is shared as `tests/data/foreign.cdxml`) opens from CDX to the same document and notes; the printed example; every cut of two synthetic files is refused; random corruption is never a panic; the hostile string (run starts jumping between 0 and 65535) is refused fast; sizes, trailing bytes, code pages, bounds, unknown items. Golden cases: `tests/data/log/cdx.json` (two files, three refused requests); `tests/parity.mjs` holds the module to the native bytes. e2e: a `.cdx` opened by keyboard (focus on Open, Enter) and by touch (tap on the Open button of the file palette), and a cut one refused in words.

Not built: writing CDX; CDX inside Office documents; the Windows clipboard. Not read: arrowhead properties, colours, font faces and sizes, `NumHydrogens`, objects other than the ones CDXML reads. Open Babel proof (E17): `tools/fidelity/cdx.py` is written but has not been run (no Open Babel here): not measured.
