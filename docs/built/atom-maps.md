# Atom-to-atom maps (plan-11), built

An atom has a field `map` in `mzdraw/1`: a whole number 1..=999 (`doc::MAX_MAP`), written only when set (0 or absent is none). Two commands carry it, with exact inverses (`SetAtom`, `DropAtom`): `{"op":"atom.set","id":3,"map":4}` (`map` 0 takes it away) and `{"op":"atom.add",...,"map":4}`; COO 16 approved the field (`map`, integer 1..999, absent = none) and marked it `mzlab:false` in the table until mzLab adopts it (`FieldSpec::mzlab`, `"mzlab":false` in `"out":"schema"`); a number above 999 is refused (`error.draw2.map`) and changes nothing. The row is in the table of `schema.rs` (`docs/mzdraw.md`, `"out":"schema"`). The property test of `crates/mzdraw/tests/ops.rs` draws maps (set, changed, taken away, refused) among its operations.

The map API other slices use (tp-02, tp-03): `Atom.map: u16`, `Document::mapped()` (how many atoms carry a map), `Document::maps_lost(kind)` (how many map numbers the output `kind` of `save` cannot hold), `Editor::set_map(n)` and `Editor::set_map_text(text)` (the page sends the raw field text; only whole numbers 0..=999 pass, else `error.draw2.map`; the focused atom, else the only selected one; one undo step), the `Op::AtomSet { map: Option<u16>, .. }` field, and `crates/mzdraw/src/maps.rs` (the readers and the V2000 writer). `mzlab-mol` (rev `ccd4680`) has no map in its `Atom`: its readers drop the number, so this layer reads it from the text and writes it back after `mzlab-mol` has written the rest. That is a gap for COO 16 (a field `map` in `mol/1`); until then maps live here.

Read: RXN and RD files and molfiles, V2000 (the `mmm` field of the atom line) and V3000 (`AAMAP`, the field after the coordinates); SMILES, the atom class of a bracket atom (`[CH3:4]`; `[*:n]` stays the number of an R group); KET `mapping` (read and written as the KET of Ketcher names it; not checked against a schema here, the schema was not read). Write: the same places (`save` as `molfile`, `molfile-v3000`, `rxn`, `sdf`, `smiles`, `ket`; also `mzdraw` and `svg`, which carries the document). CDXML and CML have no place for maps and do not write them: the loss is reported, never silent: a `replay` request with `report` carries `"lost":[{"key":"draw2.export.mapsLost","n":2}]` in `draw-result/1` (only when something is lost), `Editor::lost_on_save(kind)` and `Document::maps_lost(kind)` give it to the page and the CLI, and the page says it under Save after the file is written. On read, `map` 0 (or an empty field) means none and is not counted. A read never drops silently either: a map field that is no whole number 1..=999 (negative, above 999, not a number; KET `mapping` too) is read as no map and counted (`Imported::maps_left`, note `draw2.import.mapsLeft`); a structure with one number on two atoms is kept and counted (`maps_duplicate`, `draw2.import.mapsDuplicate`); the same number in a reactant and a product is the point of a map and is not reported. The writers pad a short atom line and never skip a number.

Display: the number at the lower right of the atom, in the small size, on the screen and in the SVG (one display list). Setting `display.maps` (`on` by default, `off`; a row of the `set` section of `"out":"schema"` and `display` of the settings schema): `{"set":["display.maps=off"]}` in a request, `Editor::set`; stored as the key `maps` of the `style` object of the settings file, written only when off. On the page: the field "Atom map" and the button Set of the side panel act on the focused atom (key Home, arrows) or the only selected one; Enter in the field applies it; the module judges the number.

Proof: `crates/mzdraw/tests/maps.rs` (an esterification with maps 1..6 round trips through RXN V2000 and V3000 and molfile V3000 with the same numbers on the same atoms; `[CH3:1][OH:2]` in and out; KET; the inverse; the display; the lost list); `tests/data/log/atom-maps.json` (golden, wasm == native); `tests/e2e.mjs` (touch and keyboard); `tools/fidelity/maps.py` in the layout of plan-03 (RDKit reads our RXN and SMILES for the 20 synthetic reactions of `tests/data/fidelity/maps-set.txt`; reference `tests/data/fidelity/maps.json`, read by `maps.rs` with no Python: our file's hash, RDKit's maps).

Not built: automatic mapping (`map:auto`), `trasf/1` export (plan-12), maps in CDXML and CML (reported as lost, not written), maps in the picture of a pasted PNG beyond the document it carries, a map number on a group label atom of a V3000 R group beyond the atom line, a `map` field in `mol/1` (mzLab).
