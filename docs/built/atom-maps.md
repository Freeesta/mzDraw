# Atom-to-atom maps (plan-11), built

An atom has a field `map` in `mzdraw/1`: a whole number 1..=999 (`doc::MAX_MAP`), written only when set (0 or absent is none). One command sets it, with its exact inverse (`SetAtom`): `{"op":"atom.set","id":3,"map":4}`; `map` 0 takes it away; a number above 999 is refused (`error.draw2.map`) and changes nothing. The row is in the table of `schema.rs` (`docs/mzdraw.md`, `"out":"schema"`). The property test of `crates/mzdraw/tests/ops.rs` draws maps (set, changed, taken away, refused) among its operations.

The map API other slices use (tp-02, tp-03): `Atom.map: u16`, `Document::mapped()` (how many atoms carry a map), `Document::maps_lost(kind)` (how many map numbers the output `kind` of `save` cannot hold), `Editor::set_map(n)` (the focused atom, else the only selected one; one undo step), the `Op::AtomSet { map: Option<u16>, .. }` field, and `crates/mzdraw/src/maps.rs` (the readers and the V2000 writer). `mzlab-mol` (rev `ccd4680`) has no map in its `Atom`: its readers drop the number, so this layer reads it from the text and writes it back after `mzlab-mol` has written the rest. That is a gap for COO 16 (a field `map` in `mol/1`); until then maps live here.

Read: RXN and RD files and molfiles, V2000 (the `mmm` field of the atom line) and V3000 (`AAMAP`, the field after the coordinates); SMILES, the atom class of a bracket atom (`[CH3:4]`; `[*:n]` stays the number of an R group); KET `mapping` (read and written as the KET of Ketcher names it; not checked against a schema here, the schema was not read). Write: the same places (`save` as `molfile`, `molfile-v3000`, `rxn`, `sdf`, `smiles`, `ket`; also `mzdraw` and `svg`, which carries the document). A format with no place for maps (`cdxml`, `cml`) lists them as lost: `Document::maps_lost("cdxml")` is the count; the page and the CLI do not print it yet.

Display: the number at the lower right of the atom, in the small size, on the screen and in the SVG (one display list). Setting `display.maps` (`on` by default, `off`): `{"set":["display.maps=off"]}` in a request, `Editor::set`; stored as the key `maps` of the `style` object of the settings file, written only when off. On the page: the field "Atom map" and the button Set of the side panel act on the focused atom (key Home, arrows) or the only selected one; Enter in the field applies it; the module judges the number.

Proof: `crates/mzdraw/tests/maps.rs` (an esterification with maps 1..6 round trips through RXN V2000 and V3000 and molfile V3000 with the same numbers on the same atoms; `[CH3:1][OH:2]` in and out; KET; the inverse; the display; the lost list); `tests/data/log/atom-maps.json` (golden, wasm == native); `tests/e2e.mjs` (touch and keyboard); `tools/fidelity/maps.py` (RDKit reads our RXN and SMILES for 20 synthetic reactions; reference `tools/fidelity/maps-reference.json`).

Not built: automatic mapping (`map:auto`), `trasf/1` export (plan-12), maps in CDXML and CML, maps in the picture of a pasted PNG beyond the document it carries, a map number on a group label atom of a V3000 R group beyond the atom line, a `map` field in `mol/1` (mzLab).
