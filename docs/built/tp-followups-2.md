## 1. `lens-1.json` (tp-04 follow-up)
`docs/schemas/lens-1.json` is the key table of `"out":"lens"` (`lens/1`), in the style of `draw-result-1.json` and `tptable-1.json`: the three objects (top level, `arrows[]`, `skipped[]`) with `x-key-order`, `required`, the reasons of `skipped` as an enum. `tests/lens.rs::the_key_table_file_says_what_the_module_writes` reads the file with `include_str!` (no JSON Schema validator is a dependency) and asserts, on the raw text the module writes, that the keys of each object come in the order of `x-key-order`, that each declared key has a property and the other way round, and that the reasons of the file are those the module writes.

## 2. The gap rule `crossing` for secondary and skipping arrows (tp-05b follow-up)
**The rule.** After the rules `slope`, `length`, `label` and the primary `crossing` have set every gap of a component, `pathway::long_gaps` looks at the arrows that are not primary (a secondary arrow, which may join adjacent layers, or one that skips a layer; a primary arrow always joins adjacent layers). Each such arrow, clipped at the route boxes of its two ends, is tested against the route box (box plus `pathway.margin`) of every other structure in the columns it spans, ends included. An arrow that meets a box widens, by one `pathway::CROSSING_STEP`, the gaps that move it off the box (below); all arrows of a round widen together, and the round is repeated, at most `CROSSING_STEPS` (400) rounds, so a gap grows by at most 20 bond lengths.
**Which gaps.** For the first box the arrow meets (lowest layer first, then the box centre nearest the arrow, then the smaller index): a box in an end column is cleared by a flatter arrow, so every gap the arrow spans grows; a box in a layer between is cleared by moving the height of the arrow at that layer away from the box centre, which is a wider part before the layer (the arrow is nearer its end) or after it (nearer its start). The choice is the sign of (rise of the arrow) x (arrow minus box centre), which is the same for an arrow and its mirror image in y, so the rule is symmetric; the gaps of a round are the union of the spans of all arrows, so the result does not depend on the order of the arrows (both tested on the rule alone).
**At the bound.** Nothing is promised that a gap can do: an arrow in a straight chain passes the middle box whatever the gaps are. The state kept is the first round with the fewest arrows still meeting a box (round 0, the gaps as they were, is a candidate), so the rule never leaves more crossings than it found. What still meets a box is the keyed finding `std.scheme.gapLimit` (one per gap the arrow spans; `objects` the long arrows that span it and still meet a box; the text of its row in the request table says so) and, as always, `std.scheme.crossing`. A widened gap is reported as `std.scheme.gapRaised` with rule `crossing`; its `arrows` are now all arrows that span the gap.
**What it did** on the 199 seeded random DAGs of 5 to 12 structures tried while building it: 284 crossings before, 189 after (the others are the cases no gap clears, each reported as `gapLimit`). The DAG of `tests/data/pathways/dag.json` keeps its one crossing (the arrow 0 -> 3 stays at the bound; the test that pins it is unchanged). The convergent DAGs of the golden files `pathway.json`, `pathway-page.json`, `pathway-label.json` and `tp-import.json` now lay out with a wider gap and no crossing where they had one; those goldens were re-blessed (the old byte count of each diff is only the moved coordinates and the `std` output).
**Cost.** The columns are sorted by y once; a test of one arrow costs O(log P + hits) per column it spans (the same binary search as the primary rule, now shared as `near`), so a round costs O(E_long x span x (log P + hits)) and the rule at most 401 rounds. `scaling_the_long_rule_alone_is_linear_in_the_arrows` builds columns where one arrow is never cleared (so all 401 rounds run) and asserts, on the thread CPU clock (`tests/support/timing.rs`, best of seven, no floor, no wall-clock figure), that four times the arrows cost less than seven times the time. The caps (1000 structures or arrows, a cycle) are checked before any of this.
**Tests** (`tests/pathway_gap.rs`): a secondary arrow and skipping arrows widen the gaps they span and leave no crossing; a chain with a skipping arrow no gap clears gives the limit on both gaps and the crossing, with the gaps as they were; over 80 seeded DAGs no primary arrow grazes and every crossing is named by a `gapLimit`; two runs of a layout are equal in centres, gaps, limits, crossings and operations (30 DAGs under three settings); the rule alone widens the gap before the box for a rising arrow, is equal for a mirror image in y and for any order of the arrows; golden cases wasm == native for a secondary arrow, skipping arrows and the unclearable chain.
