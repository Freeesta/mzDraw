# Digest `digest/1`, built

(plan-23; `crates/mzdraw/src/digest.rs`; section "Digest" of docs/mzdraw.md; one row in the `request` section of the table, `schema::REQUEST`.) `"out":"digest"` answers a few hundred bytes for an agent that cannot see the drawing, keys in a fixed order, numbers through `mzlab_mol::fixed`, written by hand: per connected structure, left to right, `ids` (atom ids as ranges), `formula` (Hill, the formula of the outline line with the ASCII minus), `box` (x0, y0, x1, y1, bond lengths, one decimal, label ink included), `labels` (`[id,text]` of every atom that is not a plain carbon and every abbreviation or R group), `stereo` (`[bond,"wedge"|"hash"|"wavy",narrow-end atom]`), `rings`; then `objects` (`[id,kind,box]`), `clearance` (the smallest gap between two structure boxes; `null` with fewer than two) and `std` (counts of `std/1` findings by key). No `draw_edit/1` op, no new exit code: with `report` or `expect` the digest is the `out` of a `draw-result/1` (a false expectation is exit 1 with the document on stdout). The CLI twin is `{"import":...,"log":[...],"out":"digest"}`; the page's `Editor::save("digest")` is the same function, so the bytes are the same (test `the_page_and_the_replay_route_...`, golden cases `tests/data/log/digest.json`, parity wasm == native in `tests/parity.mjs`).

Caps and cost (stated plainly): the code of the module is one pass over atoms and bonds (union-find; `layout::pieces` and `route::Structures` are not used, their piece search is quadratic), but it is NOT linear for a drawing with bonds: `Document::to_mol` and `scene::label_extent` look through the bonds for every atom, so the cost is atoms times bonds (release, zigzag chain: 20,000 atoms about 1 s, 40,000 about 8 s). It is capped, not removed: atoms * (bonds + 1) above 25 million (a chain or a star of 5,000 atoms) is refused with `error.draw2.digestSize` (i18n key, exit 2). A drawing with no bond has no such limit and its cost is linear (tested). The answer is capped in bytes: at most 200 structures and 200 objects, no further structure after 12,000 bytes (the rest in `more`), per structure at most 150 labels, 50 stereo entries and 400 bytes of `ids` (a cut `ids` ends in `,+K`), the cut counted in `truncated`; under about 30,000 bytes whatever the drawing (tested). `std` is `null` with `stdSkipped` `"atoms>1000"` above 1000 atoms: the `std/1` check is quadratic in the atoms and making it linear is not part of this slice. `clearance` runs over the structures listed.

Tests (`crates/mzdraw/tests/digest.rs`): the digest of a fixed synthetic document is byte-identical to `tests/data/digest/golden.txt` and to a second run; at most 1,200 bytes for a 30-atom structure with one arrow and one text; a 200-atom structure lists every hetero atom id; every id of the digest exists in the document (300 random drawings) and the ranges cover every atom once; the formulas equal those of the outline line; the box equals the extent of the `<line>` elements of the SVG of a structure without labels (read as the SVG states them, in points, at the bond length of the style); the counts of `std` equal those of `out: std`; the work cap (a chain and a star, 5,000 atoms pass within a bound, 5,001 are refused with the key, by the editor and by the replay request); the byte bound on a hostile structure (4,000 nitrogen atoms with wedges and scattered ids) and on 3,000 structures with 3,000 objects; scaling of the code of the module on drawings without bonds (20,000 against 40,000 structures: at most 3 times the time, and a bound). Mutation: a pairwise pass over the structures added to the module makes the scaling test fail in release (20,000 structures 5.0 s, 40,000 19.5 s) where the real code takes about 0.1 s. Bonded drawings are held by the cap, not by a ratio: at 5,000 atoms the engine cost is a few hundredths of a second and a ratio would show noise only. Runner: `tests/agent_suite.rs` runs the arm `digest` with a script as the model (the digest request is one call, its answer is added to the next prompt, its bytes count in the bytes of the run).

Independent proof: `tools/digest/ref.py` (RDKit, fetched at run time in a throw-away virtual environment, never committed) reads OUR digest of each of the 200 synthetic structures of `tests/data/fidelity/set.smi` and compares each formula with RDKit's `CalcMolFormula` of the same SMILES: 200 of 200 agree (RDKit 2026.09.2, 2026-11-21; reference output `tests/data/digest/rdkit-formulas.txt`). An R group is compared by element counts (RDKit reads `*`). It shows the formulas agree on this set; it does not show the boxes, ids or labels, nor formulas of drawings with abbreviations (RDKit has no such atom). The comparison is by multiset of formulas per structure, an R group (RDKit's `*`) is matched by its element counts, and the charge text is rewritten to the digest's spelling before it: so it does not show the boxes, the ids, the labels or the abbreviations, and our SMILES import is not tested independently (both sides read the same SMILES text, each with its own reader). The box test is independent only for the geometry of the atoms (the lines of the SVG). For a long label (`Fmoc`) the box must reach about as far as the text of the SVG (font size and character count, 0.55 of the size per character): a coarse range, not a measure; the ink of a label comes from the same `scene::label_extent` that the layout uses, and no program other than ours measures it.

Not built: the arm `digest` of plan-19 has its text (`tools/agent-suite/arms/digest.md`) and a turn loop in `tools/agent-suite/run.py` (up to 8 calls of the model command per run), but no model has been run: the kill test (`report+digest` against `report`, 15 points of pass@1 on the "surgical edits" and "several structures" tasks, median bytes) is the owner's run outside CI, and its result belongs in `docs/agent-suite/`; the arm stays unproven until then.
