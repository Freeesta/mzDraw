# Hover keys (arch-cd-03)

Built from `docs/prompts/arch-cd-03-hover-hotkeys.md`; study rows B02 and B03 of `docs/study/arch-cd.md`.

## What is built
- **One table, `hotkeys::TABLE`** (`crates/mzdraw/src/hotkeys.rs`): target (atom or bond), key, Shift, Alt, command. `Editor::key` reads it before the focus keys and the tool keys; the pointer first, then the keyboard focus (the focused atom, the bond just walked). A key with no row, or with nothing under the pointer or in focus, falls through to what it did before. Every key is one undo step and is announced in the live line.
- **Over a bond** (or the bond just walked): `1` `2` `3` set the order; `W` solid wedge, `Shift+W` hashed, `Y` wavy (on a double or triple bond the bond becomes single with the mark); the same wedge key again turns the wedge around (`bond.set rev`).
- **Over an atom**: `M` Me, `E` Et, `Shift+F` CF3, `Shift+O` OH (`atom.set lab`; `OH` is a new row of `label::ABBREVIATIONS`, expansion `O`); `Alt+1` to `Alt+9` sprout a zigzag chain of that many bonds at the sprout angle (`chain`); `Shift+3` to `Shift+8` add a saturated ring of that many atoms that shares the atom as one corner, a spiro or pendant ring (`ring`; it is not a ring fused on a bond).
- **The keyboard route**: the digits, the wedge keys, `Alt+digit` and `Shift+digit` act on the focused atom or the walked bond. The group letters `M` `E` `Shift+F` `Shift+O` act on the pointer's atom only, because with a focus those letters already pick a tool (`E` is the erase tool: a tested meaning); their twins with Alt (`Alt+M`, `Alt+E`, `Alt+Shift+F`, `Alt+Shift+O`) take the focused atom too.
- **Only with the select tool or the plain single-bond tool** (the tool the page starts with) for the keys that already picked a tool (digits, W, Shift+W, Y, M, E, Shift+F, Shift+O): with a wedge, double-bond, atom or other drawing tool active they still pick tools, so "pick a tool with the key, then click" is what it was (the velocity paths rely on it). The Alt keys and `Shift+3`-`Shift+8` work with any tool; the digits on the bond just walked keep acting with any tool (`focus_key`).
- **No clash**: the keys that stand for an element (C N O S P F H B I, Shift+C, Shift+B, Shift+S) are not in the table and keep setting the element. With a drawing tool active, or over nothing, `1 2 3 W Shift+W Y M E Shift+F Shift+O` pick their tools as before (tests `over_nothing_the_keys_keep_picking_their_tools`, `the_table_has_no_clash_and_every_row_is_valid`). Only with an atom under the pointer do `M` (otherwise "bring the selection to a click"), `E` (erase tool) and `Shift+F`, `Shift+O` (atom tool F, O) mean the group; before this slice `Shift+F` and `Shift+O` over an atom set F and O as the plain letters do. **So: over an atom, with the select or the plain single-bond tool, `Shift+F` and `Shift+O` now give CF3 and OH instead of the element F and O.**
- **The page**: it sends the physical digit for a digit pressed with Shift or Alt, and the physical letter for a letter pressed with Alt (`Shift+6` types `^` on a US layout and `Alt+6` a symbol on a Mac), so the Alt keys and `Shift+3`-`Shift+8` work there; nothing else is decided in the page. **Limit, not layout independent**: on a layout whose digit row types symbols unshifted (AZERTY), the plain digits `1 2 3` of the hover keys are not reachable (the typed digit arrives with Shift held, the table has them without) and the Shift+digit rings arrive as the physical digit with Shift, which works; the Alt keys use the physical key and work. A table that matches the typed key and the physical code is the follow-up `arch-cd-03b-hover-keys-layouts`. The help ("Drawing with the keyboard") lists the table: the page asks `hotkeys()` of the module (the rows with their keys and parameters) and words them from `draw2.hot.*`.
- **CLI route**: no new operation. The keys produce `bond.set`, `atom.set`, `chain` and `ring` of `draw_edit/1`, so the log of a session replays natively to the same bytes, and the replay request has a field `keys` (`[{"key","mods","hover":{"atom":id}|{"bond":id},"focus":{"atom":id,"from":id}}]`, run through `Editor::key_over` after `events` and before `out`; a bad entry is `error.draw2.keys`) so that the key handling itself has a native test and an agent can send keys. Golden file: `tests/data/log/hover-keys.json` (parity wasm == native).

- **A key that changes nothing takes no undo step**: `1` over a single bond, `2` twice, `M` twice leave the drawing and the history as they are and say so in the live line (`draw2.say.hotNoChange`); an undo after one takes back the previous real edit.
- **A key that would lose something is refused with a keyed note and changes nothing**: a group on an atom with more than one bond (`error.draw2.hotGroup`), on a charged, isotope, radical or non-carbon atom (`error.draw2.hotAtom`: the label would replace it); a chain or ring on an atom with no free valence for the new bonds, one for the chain and two for the ring, or on a labelled atom (`error.draw2.hotValence`); a wedge key on a bond with a display kind, or `2` `3` on a dative or hydrogen bond (`error.draw2.hotKind`: the key would drop the kind).
- **The pointer first**: with the pointer over an atom the walked bond is not used (a digit picks its tool, as it does in the digit's other uses), and with the pointer over a bond the focused atom is not used.
- **Screenshots at deviceScaleFactor 2**: `docs/shots/hover-keys-bond.png`, `docs/shots/hover-keys-atom.png`.
- **Replay field `keys`** refuses an id that is not in the drawing (as the keys before it left it) or not a number with `error.draw2.keys`.

## Not built
- Touch has no hover: a tap is no pointer over an atom, so the hover keys do nothing on a finger (a pen that hovers works like the mouse; a keyboard on a tablet has the focus route). A long press that opens the same keys is not built.
- Keys over a hovered object other than an atom or a bond (arrows, texts), a ring fused on a hovered bond (the ring keys make a spiro ring on an atom), benzene on a key, rebinding of the keys (arch-std-06), new bond kinds (arch-cd-04, arch-web-20).
- The table is not the command table of arch-std-06 (not on `main`); when it lands, `TABLE` is the data to move into it.
- The group letters are labels, not a free chemical interpretation; they replace the label of the atom (a hovered atom with several bonds is labelled too, as the label tool does).
