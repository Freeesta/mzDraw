# The schema golden: one row per line

`tests/data/log/edit-schema.json` records the table of the operations (`draw-edit-schema/1`, `schema::json()`) as the list of its rows in `out`: the header, every operation, the join to the request rows, every request row and the end, each one string on a line of its own. The strings joined are exactly the bytes of `mzdraw-cli mol draw` / `{"out":"schema"}`; the comparison stays exact, natively (`crates/mzdraw/tests/replay.rs`) and for the wasm (`tests/parity.mjs`, which joins the rows). A row starts with its comma and the closing `]}` is a row of its own, so a row added in `schema.rs` (in the middle or at the end of the operations or of the request rows) adds its own lines to the golden and changes no other. Two PRs that add different rows no longer conflict in the golden; two inserts at the very same position in `schema.rs` itself still do, which is inherent.

The split is made by `schema_rows` (`crates/mzdraw/tests/replay.rs`) and written by `MZDRAW_BLESS=1 cargo test -p mzdraw --test replay`; nothing in the schema, the CLI route or the page changed. The parsed JSON of the table is the one of the old one-line golden (checked on the commit this slice started from). A test (`the_golden_table_is_one_row_per_line`, `crates/mzdraw/tests/schema.rs`) fails if the file holds the table as one line, two rows share a line, or the closing is not its own row. Not built: any change to the schema itself.
