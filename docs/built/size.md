# Size of the editor module (history)

The current size is not recorded in the repository: `tools/build_site.sh` prints it (raw and gzip) and fails above the `cap` of `tools/wasm-cap.toml`. The entries below are the history up to the last one that was written by hand, oldest first.

the module is 584,638 B (268,019 B gzip; the drawing checks `std/1` added 16,634 B) against the cap of 4,000,000 B (owner lifted the limit on 2026-11-20; revisit before the first release; the cap is now only a guard that catches a runaway). The cap was 512,000 B until the 2D layout of `mzlab-mol` was linked: the pin alone moved the module by 406 B, the layout by 36,063 B (about 22 kB of layout code, the rest its generic instances and data, no single wasteful item), and the owner raised the cap to 540,000 B for it (2026-11-20). Measured parts: the live check `check/1` (feature `mzlab`) is 82 kB; the editor with the readers of `mzlab-mol` was 398 kB at slice 1. The derived serde readers were the cost of slice 2: read by hand from a JSON value (`Op::from_value`, `Document::from_json`, the replay request), the operations gave back 53 kB and the document and the request 29 kB. Nothing is derived any more: the command log is written by hand too (`Op::write`, 3 kB less). The sorts of the standard library cost about 3 kB of module per sorted type at this optimisation level: the seven of mzDraw are one small heap sort (`m::sort_by`, 12 kB less). One `f64` handed to the formatter of the standard library (a `to_string` in the rotate announcement) cost 22 kB: numbers are written through `mzlab_mol::fixed` or serde_json. Slice 3a cost 39.9 kB: 27.7 kB for SMILES out (the writer of `mzlab-mol` and what it links), 12.2 kB for the V3000 marks, the R groups of the three forms, the records of an SDF and the list of what is out of scope. Slice 3b cost 5.7 kB (SVG 1.4 kB, PNG 4.3 kB). Slice 3c cost 11.9 kB, of which 5.9 kB came back from writing the page state and the last `json!` values of the bridge by hand (a JSON value built by the macro costs about 2 kB per object; one `f64` formatted with `{}` in the first draft of the KET reader cost 22 kB again). The copies of the standard sorts and B-trees inside `mzlab-mol` and the check (about 105 kB when measured) were the dependency's to remove: its size work (mzLab #3595, pinned here at `b27a039`) took 80.9 kB off this module (510,533 B to 429,609 B) with every golden output unchanged.
